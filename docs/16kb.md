# 16 KB page alignment

Builds apply `io.github.supermonster003.autojs6-native-alignment:1.8.3`. Every assembled application APK
is checked and reports are written to `app/build/reports/native-alignment/`.
Use `:app:verifyNativePageAlignment` to recheck existing artifacts.

The variant verifiers use AGP's `SingleArtifact.APK` directory and select APKs from its
`output-metadata.json`. IntelliJ IDEA Run (F10) can write the selected device's APK to
`app/build/intermediates/apk/debug`, while command-line builds normally use
`app/build/outputs/apk/debug`. Both paths keep the same alignment checks; no preliminary
command-line assembly or verification skip is needed. Each variant reads only its own
artifact directory, so an earlier command-line APK cannot mask an IDE build failure.
The aggregate `verifyNativePageAlignment` task continues to recheck existing artifacts
under `outputs/apk`; use the variant task with the IDE properties to recheck IDE outputs.

The gate enforces ELF PT_LOAD alignment for arm64-v8a and x86_64. Uncompressed `.so` entries also require 16 KB ZIP alignment. Third-party 32-bit alignment is advisory.

Every native dependency or toolchain upgrade must pass the gate again. Static alignment
does not prove runtime behavior: test on a device reporting `getconf PAGE_SIZE = 16384`
with compatibility mode disabled. No `android:pageSizeCompat` override is permitted.

中文: 构建门禁检查全部产物并输出 JSON 报告. 原生依赖或工具链升级后必须重新校验,
且需在页大小为 16384 的设备上关闭兼容模式后执行运行时验证.

IDEA F10 运行时, 校验任务通过 AGP 获取当前变体实际生成的 APK 目录及元数据,
支持 IDE 的 `intermediates/apk` 和命令行的 `outputs/apk` 目录, 无需预先手动构建或跳过校验.
