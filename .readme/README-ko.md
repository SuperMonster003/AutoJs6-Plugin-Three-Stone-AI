### 소개

******

3-Stone AI는 AutoJs6의 공식 AI 텍스트 생성 플러그인입니다. 사용자가 가져온 LiteRT-LM 모델을 명시적으로 선택한 CPU 또는 호환 GPU backend에서 실행하고 온라인 생성에는 사용자가 구성한 온라인 서비스를 사용합니다. 로컬 및 온라인 실행 위치는 하나의 AI Provider V2 target catalog, 제어된 스트리밍 파이프라인, 명시적 선택 경계를 공유합니다. 로컬 대상은 네트워크에 접근하거나 데이터를 업로드하지 않으며, 온라인 대상은 사용자가 명시적으로 선택한 경우에만 플러그인이 관리하는 자격 증명과 선언된 HTTPS origin에 고정되어 실행됩니다.

### 기능

******

- Android 시스템 선택기로 `.litertlm` 모델 패키지를 가져오고 검증된 복사본을 앱 전용 저장소에 보관합니다.
- 내장 목록에서 고정 버전이며 인증이 필요 없는 LiteRT Community 권장 모델을 한 번에 다운로드합니다: 앱 전용 저장소에 바로 쓰고 정확한 크기와 SHA-256을 검증한 뒤 자동으로 가져옵니다. 다운로드 중인 모델은 "로컬 모델" 섹션에 카드로 표시되며 진행률, 일시중지, 취소, 실패 시 재시도를 지원하고 중단되면 이미 받은 부분부터 이어서 받습니다. 다운로드 확인 창에는 모델의 최소 메모리 요구 사항이 표시되며 기기 메모리가 부족하면 경고합니다.
- 시스템 선택기를 열기 전에 비공개 저장 공간을 사전 확인하고, 현재 가져오기 예산과 비공개 사본의 예상 사용량을 표시하며, 복사 전에 선택한 파일을 다시 확인합니다.
- 일반 텍스트 system, user 및 assistant 기록으로 로컬 생성 요청을 만듭니다.
- AutoJs6 `ai.ask`, `ai.chat`, `ai.stream`의 `temperature`, `topK`, `topP`, `maxTokens`를 LiteRT-LM까지 전달합니다.
- AutoJs6 `structuredJson`과 `responseSchema`를 통해 LiteRT-LM 네이티브 JSON Schema 제약 디코딩을 사용하며, 완성된 값은 `JSON.parse`용 JSON 텍스트로 유지합니다.
- LiteRT-LM의 정확한 입력, 출력, 전체 token 수와 공급자 측 생성 시간을 AutoJs6 `ai.chat().usage` 및 스트림 usage 이벤트로 반환합니다.
- AutoJs6 `ai.session`으로 하나의 LiteRT-LM 네이티브 Conversation에 여러 턴의 컨텍스트를 유지하고 이후 턴에는 새 사용자 프롬프트만 전송합니다.
- 모델 SHA-256을 키로 초기화된 Engine을 재사용하여 같은 모델에 대한 연속 요청의 반복 콜드 스타트를 없앱니다.
- 가져온 각 모델을 선택적으로 한 번 초기화하고 사용 가능/호환되지 않음 상태를 저장하며 모델 관리자에서 다시 확인합니다.
- credit 역압력으로 텍스트 chunk를 순서대로 전달하고 완료, 실패 또는 취소 중 하나의 종료 상태만 게시합니다.
- "로컬 모델" 섹션에서 가져온 모델을 나열하고 이름을 바꾸고 검사하고 삭제하며, 각 카드에 모델이 차지하는 용량을 표시하고 참조되지 않은 모델 파일을 한 번에 회수합니다.
- AutoJs6에서 `cpu`, `gpu`, `npu` backend를 명시적으로 선택합니다. CPU가 기본값이며 GPU는 OpenCL 로드 검사를 통과할 때만 노출되고, NPU는 EAP runtime 미포함으로 사용 불가가 명시됩니다.
- 설정 > 모델 및 서비스에서 기본 제공 및 사용자 지정 온라인 서비스, Android Keystore 자격 증명, 하나뿐인 기본 대상 (온라인 모델 또는 로컬 모델), 종량제 네트워크 및 명시적인 제한형 연결 테스트를 관리합니다. 서비스는 전체 화면 "서비스 세부정보" 페이지에서 편집합니다: 서비스마다 여러 모델을 추가하고 끌어서 순서를 바꾸며 우선 모델을 정할 수 있고, 체크 표시를 눌러야 저장됩니다.
- 각 런처 대화를 하나의 로컬 또는 온라인 대상 스냅샷에 고정합니다. 메시지가 있는 대화에서 변경하면 새 대화를 권장하고 계속하려면 명시적 확인과 변경 기록이 필요합니다.
- 각 어시스턴트 응답에 실제 target/provider/model/locality 스냅샷을 저장합니다. 다시 생성은 기록된 원래 대상을 정확히 재사용하며 대상 정체성이 바뀌거나 사용할 수 없으면 명확히 실패하고 현재 대화 대상으로 자동 대체하지 않습니다.
- 로컬 및 클라우드 생성 실패를 선택된 경계에 유지합니다. 런처 chat은 민감한 정보가 없는 제한된 실패 원인을 추가하고 경계를 넘는 자동 대체가 없었음을 명시하며 부분 출력을 유지한 채 명시적인 수동 대상 전환을 제공합니다.
- 온라인 OpenAI 호환, Anthropic Messages, Gemini GenerateContent 대상에서 네이티브 도구 호출 지원. 스트리밍 인수, 병렬 호출, 결과 제출 후 이어서 생성 포함.
- 모델별 설정과 협상된 AI Provider 2.1을 통한 온라인 JPEG/PNG 입력 및 이미지 도구 결과.
- GitHub 프로젝트의 공개 목록에서 온라인 사전 설정 모델을 업데이트합니다. 자동 업데이트는 기본으로 활성화되며 "모델 및 서비스" 화면을 열 때 24시간마다 한 번 확인합니다. "온라인 서비스" 섹션 메뉴에서 자동 업데이트를 끄거나 수동으로 새로 고칠 수 있습니다. 데이터 요금제 네트워크 설정을 따르며 오프라인이나 업데이트 실패 시 캐시 또는 내장 목록을 계속 사용하고 저장된 서비스와 사용자 지정 모델 ID는 변경하지 않습니다.
- 사전 설정 모델을 공급업체별로 분류하고 OpenRouter 선택 항목에 Qwen, Kimi, GLM, Grok, Meta, MiniMax 등을 추가하며 정확한 모델 ID를 유지합니다.
- 독립 설정을 평면 그룹, 일관된 행과 중앙의 둥근 대화상자로 통일했습니다. 언어, 야간 모드, 테마 색과 런처 아이콘은 확인 후 적용되며 취소하면 저장 값이 유지됩니다. 색은 기본적으로 AutoJs6를 따르며 공통 팔레트, HEX/RGB 입력과 부분 미리 보기를 제공합니다. 중립 배경색은 고정하고 컨트롤은 선택한 테마를 따릅니다. 런처 기본값은 자동 적응형이며 업데이트 시 명시적 선택을 유지합니다.
- 채팅 답변 생성이 채팅 화면과 분리되었습니다: 화면 회전, 다크 모드 전환, 언어나 메시지 글꼴 크기 변경 중에도 생성이 계속되고, 채팅 화면을 벗어나 있는 동안 끝난 답변도 돌아오면 전체가 표시됩니다 (시스템이 앱 프로세스를 종료하면 중단됩니다). "중지"를 누르거나 새 대화, 대화 전환, 모델 전환, 메시지 삭제를 하면 1초 안에 온라인 요청을 끊으며, 중지한 뒤에는 사용량이 더 늘지 않습니다.
- 온라인 서비스에서 기본 추론 강도 (기본, 낮음, 보통, 높음, 매우 높음, 최대; "기본"이면 모델이 결정)를 설정할 수 있고, Anthropic 서비스는 빠른 모드 (답변이 빨라지는 대신 요금이 높음)를 기본으로 켤 수 있습니다; 채팅 중 현재 대화에만 적용되도록 바꿀 수 있으며 바꾼 값은 대화와 함께 저장됩니다. 모델이 선택한 단계를 지원하지 않으면 가장 가까운 낮은 단계를 사용합니다. 스크립트가 플러그인 인터페이스로 AI를 호출할 때는 이 두 항목을 쓰지 않습니다.
- 모델 전환은 아래에서 열리는 패널에서 합니다: 즐겨찾기한 모델은 맨 위 "즐겨찾기" 그룹에, 나머지는 서비스별 그룹에 표시되며 각 모델은 한 번만 나타납니다; 검색 결과는 그룹으로 나누지 않습니다; 각 행 아래에 소속 서비스 (로컬 모델은 파일 크기)를 표시하고 이미지 입력, 추론, 빠른 모드도 표시합니다; 패널에서 현재 대화의 추론 강도와 빠른 모드를 바로 바꿀 수 있고, 아래쪽 "모델 및 서비스 관리"로 모델 설정을 엽니다. 채팅 화면 위쪽에 현재 대화의 추론 강도와 빠른 모드가 표시됩니다.
- 모델의 생각 과정을 표시합니다 (Claude 5 이상, Gemini 2.5 이상, 그리고 DeepSeek 처럼 생각 내용을 돌려주는 OpenAI 호환 서비스): 생성 중에는 답변 위 카드에 생각 내용이 실시간으로 표시되고, 완료되면 "N초 동안 생각함"으로 접히며 탭하면 펼치거나 접습니다. 설정의 "생성 중 생각 내용 표시"와 "완료 후 자동으로 접기"는 기본으로 켜져 있습니다. 생각 내용은 대화와 함께 저장되지만 소리 내어 읽기, 메시지 검색, 복사에 포함되지 않으며 스크립트에도 돌려주지 않습니다.
- 대화 기록은 v6 형식을 사용하며, 대화별 추론 강도와 빠른 모드, 답변별 생각 내용과 생각 시간도 저장합니다. 1.5.0 이하에서 저장한 대화도 계속 열 수 있습니다.
- 입력란 안의 마이크: 탭하여 말하면 인식된 텍스트가 커서 위치에 들어가며, 확인한 뒤 보낼 수 있습니다. 길게 누르면 음성 대화가 시작되어 말한 내용을 바로 보내고, 응답을 다 읽은 뒤 다시 듣습니다.
- 응답 읽기: 응답을 길게 눌러 "읽어 주기"를 선택하거나, 설정 > 음성에서 "응답 자동 읽기"를 켜면 새 응답을 생성하면서 읽습니다. 제목과 목록 기호는 읽지 않고, 코드 블록과 표는 한 문장으로 알려 줍니다.
- 3-Macaw Speech 디지털 어시스턴트의 `VOICE_COMMAND`에 응답: 전원 버튼을 길게 누르고 말한 뒤 "3-Stone AI"를 탭하면 새 대화에서 질문을 바로 보내고 답을 읽어 줍니다.

### 음성

******

받아쓰기와 읽기는 Android 시스템 인터페이스(`RecognizerIntent`, `TextToSpeech`)를 사용합니다. 3-Stone AI는 직접 녹음하지 않으며 마이크 권한도 요청하지 않습니다. 3-Macaw Speech가 설치되어 있으면 설정 > 음성의 "3-Macaw Speech 우선 사용"이 기본으로 켜져 있어, 받아쓰기는 오프라인 인식 창을 열고 읽기는 오프라인 음성을 사용합니다. 설치되어 있지 않거나 옵션을 끄면 휴대폰에 있는 인식 앱과 기본 음성 합성 엔진을 사용합니다. 1.4.0의 음성 대화는 매 차례 인식 화면을 엽니다. 응답을 읽는 동안 입력란 위의 상태 표시줄을 탭하면 중단하고 바로 다음 말을 할 수 있으며, 상태 표시줄의 버튼으로 종료할 수 있습니다.

- **음성 인식 앱이 여러 개라 매번 선택해야 하나요?** "3-Macaw Speech 우선 사용"을 켜 두면 3-Macaw Speech를 바로 사용합니다. 끄면 시스템이 결정하며, 시스템 선택 화면에서 기본 앱을 지정할 수 있습니다.
- **저사양 휴대폰에서 문장 사이에 끊김이 있나요?** 일부 음성(MeloTTS, Kokoro 등)은 느린 휴대폰에서 읽는 속도보다 합성이 느립니다. 3-Macaw Speech에서 기본 음성을 AISHELL-3, Piper 또는 Matcha로 바꾸세요.
- **마이크를 누르면 인식 모델이 없다고 나오나요?** 3-Macaw Speech 인식 창이 모델 다운로드를 안내합니다. 그전까지 3-Stone AI는 다른 인식 앱으로 자동 전환하지 않습니다. 잠시 다른 앱을 쓰려면 "3-Macaw Speech 우선 사용"을 끄세요.
- **3-Macaw Speech 디지털 어시스턴트로 질문하려면?** 3-Macaw Speech를 기본 디지털 어시스턴트로 설정하고, 전원 버튼(또는 홈 버튼)을 길게 눌러 말한 뒤 결과 카드에서 "3-Stone AI"를 탭하세요. 3-Stone AI가 새 대화를 열어 질문을 바로 보내고 답을 읽어 줍니다. 잠겨 있으면 먼저 잠금을 해제하세요. 이전 질문 후 10초가 지나지 않았으면 텍스트는 입력란에만 들어가고 보내지지 않습니다.
- **인식된 텍스트는 어디로 가나요?** 입력한 텍스트처럼 선택한 모델로 보내지며, 온라인 모델은 이를 제공업체로 보냅니다. 3-Macaw Speech는 완전히 오프라인으로 동작하며, 다른 인식 또는 읽기 앱은 네트워크를 사용할 수 있습니다.

### 플러그인 인터페이스

******

호스트는 다음 식별자로 플러그인을 검색하고 호출합니다:

```text
service action: org.autojs.plugin.AI_PROVIDER
plugin id: three-stone-ai
protocol provider id: autojs6.three-stone-ai
engine: three-stone-ai
variant: default
protocol: V2 (2.0 / 2.1)
required host build: 5276
```

AI Provider V2는 `local:*` 및 `profile:*` 대상을 하나의 페이지형 catalog로 공개합니다. 각 대상은 provider, model, locality, 구성/가용성, capabilities, limits, controls, HTTPS origins를 개별적으로 선언합니다. 로컬 전용 catalog는 ON_DEVICE/NONE을 선언하고 online profile이 있으면 HYBRID/PLUGIN_MANAGED와 HTTPS origins의 정확한 합집합을 선언합니다. 로컬 backend profile은 선택적 target control이며 사용할 수 없는 profile이나 대상으로 자동 전환하지 않습니다.

호스트 build 5276 이상과 Android 7.0 이상이 필요합니다. 빌드에는 armeabi-v7a, arm64-v8a, x86, x86_64, universal APK가 포함됩니다. x86 및 armeabi-v7a 기기에서는 해당 개별 APK를 사용하세요. 앱 화면, 온라인 AI 및 호스트 플러그인 연동을 지원합니다. LiteRT-LM 로컬 추론에는 arm64-v8a 또는 x86_64와 APK의 해당 네이티브 라이브러리가 필요합니다. universal APK에는 64비트 라이브러리만 포함되어 32비트 전용 기기에 설치할 수 없습니다.

******

### 호스트 통합 상태

******

> AutoJs6(빌드 5276 이상)에서 `ai.catalog()`는 가져온 로컬 모델과 구성된 온라인 profile을 하나의 대상 카탈로그로 반환하며 정확한 ID, 공급자, 모델, 위치, 구성/가용 상태, 기능, 제어, 제한, origin 및 로컬 backend profile을 포함합니다. 정확한 `target`을 `ai.ask`, `ai.chat`, `ai.stream` 또는 `ai.session`에 전달합니다. `target`만 지정하면 공식 3-Stone AI 플러그인을 선택하고 `plugin: true`는 플러그인이 선언한 기본 대상을 사용합니다. 로컬 대상은 `cpu`, `gpu`, 사용 불가 `npu`를 제공할 수 있지만 온라인 대상에는 로컬 실행 profile이 없습니다. backend 또는 대상을 사용할 수 없으면 fallback 없이 실패하며 로컬/온라인 경로도 자동으로 전환되지 않습니다. 완료 및 스트리밍 응답은 target, plugin, profile, reasoning, finish reason, 전체 usage 및 공급자 측정 시간을 제공합니다. 안정된 오류는 공급자 누락/비활성화, 대상 알 수 없음/미구성/사용 불가/기능 불일치 및 backend 사용 불가를 구분합니다. `responseSchema`는 구조화 출력을 활성화하고 schema 없는 `structuredJson: true`는 기본 object 루트를 사용하며 영구 세션은 모든 턴에서 같은 target, schema 및 선택 backend를 고정합니다.

독립 서명 앱이 플러그인에서 AI 접근을 요청하고 앱 및 설치 정보에 승인을 연결하며, 설정에서 철회하면 실행 중인 요청도 중지. 이 권한은 로컬 모델과 저장된 온라인 계정을 포함하며 온라인 호출은 유료 할당량을 사용할 수 있습니다. Node.js, Bun 및 Worker에서 ai.hasAccess()와 ai.requestAccess()를 사용합니다.

### 보안 및 개인정보 보호

******

사용자가 시작한 권장 모델 다운로드, 사용자가 구성한 온라인 대상 요청, "모델 및 서비스" 화면에서 GitHub의 공개 사전 설정 모델 목록 업데이트에 `INTERNET` 권한을 사용합니다. 목록 업데이트에는 API 키가 필요 없으며 추론을 호출하지 않고 플러그인 활성화나 로컬 생성 중에는 시작하지 않습니다. 광범위한 저장소 권한은 요청하지 않습니다. 모델 파일 다운로드는 변경 불가능한 HTTPS 리비전, 고정 크기와 SHA-256을 사용하고 앱 전용 `files/models`의 부분 파일에만 쓰며 (중단 후 이어받기 가능), LiteRT-LM 헤더, 크기, 다이제스트, flush, fsync가 모두 통과한 뒤에야 가져오기 경로로 넘겨 원자적으로 활성화합니다. 가져오기는 계속 선택기 URI만 읽고 검증 사본을 `files/models`에 써서 원자적으로 활성화합니다. 기존 호스트용 Provider는 AutoJs6 패키지, UID, 서명, target metadata 및 선언된 origin 경계도 검증합니다. 음성 기능은 마이크 권한을 요청하지 않으며 녹음은 인식 앱이 합니다. 인식된 텍스트와 읽는 텍스트는 로그에 기록하지 않고, 음성으로 입력한 메시지는 입력한 메시지와 똑같이 저장됩니다. 모델이 돌려준 생각 내용은 기기의 대화 기록에만 저장되며, 이후 턴에서 온라인 서비스로 다시 보내지 않고 플러그인 인터페이스로 스크립트에 돌려주지도 않습니다.

### 운영 제한

******

- 모델 가져오기에는 8 GiB의 엄격한 상한이 있고 완료 후 최소 256 MiB의 여유 공간이 필요합니다.
- 완료되지 않은 모델 다운로드는 하나만 유지되며, 다른 모델의 다운로드를 시작하면 버려집니다 (확인 창에 안내됨). 다운로드는 `files/models/.download-<sha256>.part`에 쓰입니다: 일시중지, 네트워크 끊김, 앱 종료, 프로세스 종료 시에는 이 파일을 유지하고, 계속하거나 재시도할 때는 이미 받은 부분을 다시 검증한 뒤 이어서 받습니다; 취소, 잘못된 내용, 다이제스트 불일치 시에는 삭제합니다. 콜드 스타트 시 아직 가져오지 않은 권장 모델의 최신 부분 파일은 일시중지 상태로 복원하고 나머지는 삭제합니다.
- 다운로드하거나 가져온 로컬 모델은 앱 전용 데이터 (`files/models`)에 저장되며, 차지하는 용량은 "로컬 모델" 섹션의 카드와 모델 전환 패널에 표시됩니다. 플러그인을 제거하거나 앱 데이터를 지우면 이 모델들도 함께 삭제됩니다; 이전에 다른 위치로 다운로드한 모델 파일은 "모델 파일 가져오기"로 가져올 수 있습니다.
- Application scope 단일 가져오기 coordinator가 Activity 재생성 중에도 작업을 유지합니다. Fsync된 pending journal로 콜드 스타트 복구와 stale `.incoming`, `.current`, `.pending` 임시 파일 cleanup을 수행합니다. 복구는 현재 시도가 새로 만들고 current metadata로 게시한 적 없는 destination만 삭제하며 게시됨, current 및 이전 hash 세대는 보존합니다.
- 분리된 `:provider` 프로세스와의 프로세스 간 경쟁을 피하기 위해 가져오기 중에는 이전 SHA-256 hash 이름 모델 세대를 자동 삭제하지 않습니다. "로컬 모델" 섹션에서 catalog 모델을 삭제하고 catalog에서 더 이상 참조하지 않는 hash 이름 파일을 회수할 수 있습니다.
- 프로세스에서 활성 생성 세션은 최대 1개입니다. 요청 descriptor는 비동기 작업 전에 복제되고 프로토콜 quota에 따라 닫힙니다.
- Provider는 모델 SHA-256과 backend profile 쌍을 키로 초기화된 Engine을 최대 하나만 캐시합니다. 같은 쌍은 재사용하며, 어느 키든 바뀌거나 5분 유휴 또는 명시적 메모리 압박 시 안전하게 해제합니다.
- 모델 확인은 현재 기기와 번들 런타임에서 `Engine.initialize()`가 성공하는지만 증명합니다. 출력 품질은 평가하지 않으며 기기 또는 런타임 변경 후 다시 확인할 수 있습니다.
- Provider가 선언하는 컨텍스트 상한은 256 KiB, 출력 상한은 64 KiB입니다. 요청과 모델은 더 낮은 상한을 적용할 수 있습니다.
- 응답 schema는 64 KiB 이하의 JSON object여야 합니다. 지원 keyword는 포함된 LiteRT-LM/LLGuidance 런타임 구현을 따르며, 완성된 출력은 엄격히 parse 및 검증하므로 전체 JSON 값에 충분한 `maxTokens`를 확보해야 합니다.
- `maxTokens`는 1부터 2,147,483,647까지의 정수입니다. 생략하면 출력 token 수는 모델/엔진 기본값에 맡기며, provider의 64 KiB 출력 안전 한도는 유지됩니다. `temperature`는 유한한 0 이상의 값, `topK`는 양의 정수, `topP`는 0부터 1까지의 유한한 값이어야 합니다. 세 sampling 설정을 모두 생략하면 모델/엔진 기본값을 유지하고, 일부만 지정하면 생략된 항목을 LiteRT-LM 기준값 `topK: 1`, `topP: 0.95`, `temperature: 1`로 채웁니다.
- 스트리밍은 유한 credit과 제한된 chunk를 사용해 무제한 버퍼 또는 역압력 없는 callback을 방지합니다.
- Usage token 수는 LiteRT-LM Conversation의 KV cache 및 decode 카운터에서 직접 가져오며 문자 수로 추정하지 않습니다. `durationMillis`는 플러그인 생성 호출만 측정하고 호스트 탐색, 바인딩, 모델 열거 및 디스패치 시간은 제외합니다.
- 영구적인 `ai.session`은 하나의 활성 턴만 허용하고 정상 완료 후 네이티브 Conversation을 유지합니다. 취소, timeout, 생성 실패 또는 명시적 닫기 후에는 다시 만들어야 합니다.
- 취소, 세션 닫기 및 timeout은 결과 게시를 중단하고 하나의 종료 상태로 요청을 끝냅니다.
- 설정 > 모델 및 서비스에서 서비스의 "서비스 세부정보"를 열고, 모델 목록에서 이미지 입력을 지원하는 모델의 행 메뉴로 "이미지 입력"을 켜세요. 기존 서비스는 기본적으로 꺼져 있습니다. 이미지는 해당 서비스로만 전송됩니다. LiteRT와 영구 ai.session은 텍스트 전용입니다. Agent 화면 캡처에는 Android 11+, 호환되는 AutoJs6 및 AI Agent, observe 그룹, 선택한 정확한 모델의 이미지 입력 활성화가 필요합니다.
- AiGoCode gpt-5.6-sol은 Provider 1.2.0 / build 218에서 실제 초기 이미지 및 도구 결과 이미지 검증을 통과했습니다. 합성 이미지를 사용한 이 검증은 다른 대상의 지원이나 전체 Agent 시각 작업의 성공을 증명하지 않습니다.
- 온라인 실패는 선택적 `providerCode` 필드에 고정된 `ONLINE_*` 분류만 제공합니다. 알 수 없는 예외에는 분류가 없으며 URL, 자격 증명, 서비스 응답 또는 원래 예외 텍스트는 포함하지 않습니다. 실패 코드와 재시도 정책은 변경되지 않습니다.

### 선언하지 않는 기능

******

- 플러그인 인터페이스는 Reasoning 출력을 선언하지 않으므로 스크립트는 생각 내용을 받지 않습니다 (생각 과정은 런처 채팅에서만 표시). 로컬 LiteRT-LM 대상은 여전히 tools를 선언하지 않습니다.
- 네이티브 도구는 최대 16라운드와 동시 대기 호출 32개를 허용합니다. 결과는 대기 중인 배치와 정확히 일치해야 하며 컨텍스트/출력 제한, 취소, 원래 기한이 유지됩니다. 영구 ai.session과 함께 사용할 수 없고 초기 기록의 tool 역할은 허용하지 않습니다.
- 임의 URL에서 모델 파일을 다운로드하는 기능은 지원하지 않습니다. 프로젝트의 공개 목록에서 사전 설정 모델을 업데이트할 수 있지만 서비스를 만들거나 계정의 접근 권한을 조회하지는 않습니다. 런처 채팅과 AI Provider V2에는 가져온 로컬 모델과 명시적으로 설정된 온라인 서비스만 표시되며 로컬 모델 다운로드는 고정된 내장 권장 목록으로 제한됩니다.
- NPU 추론은 선언하지 않습니다. profile은 `npu-runtime-not-packaged` 사유의 `unavailable`로 검색됩니다. GPU는 `libOpenCL.so`를 로드할 수 있을 때만 선언되며 `.litertlm` 확장자만으로 모델 초기화를 보장하지 않습니다.

* `기능` 채팅에서 첨부 파일을 추가할 수 있습니다: 입력란 왼쪽의 "+"를 눌러 이미지나 파일을 선택하며, 메시지당 최대 20개입니다. 지원하는 파일은 이미지 (장당 5 MB 이하, 너무 큰 이미지는 자동으로 축소), UTF-8 텍스트 파일 (txt, md, json, csv, 코드 파일 등, 256 KB 이하), PDF (32 MB 및 100페이지 이하)입니다. 이미지를 보내려면 현재 모델에 "이미지 입력"이 켜져 있어야 하고, PDF는 현재 제공자가 Anthropic 또는 Gemini인 서비스에만 보낼 수 있습니다 (Gemini는 요청 한 번의 첨부 파일 합계가 20 MB 이하). 로컬 모델은 아직 첨부 파일을 지원하지 않습니다. 현재 모델이 지원하지 않는 첨부 파일은 흐리게 표시되며, 제거하거나 다른 모델로 바꿔야 보낼 수 있습니다
* `기능` 첨부 파일은 메시지와 함께 앱 데이터에 저장됩니다: 메시지에 이미지 미리보기나 파일 이름이 표시되고, 누르면 다른 앱으로 열 수 있습니다. 선택했지만 아직 보내지 않은 첨부 파일은 화면을 회전하거나 앱이 종료되어도 유지됩니다. 나중에 대화를 이어 갈 때는 컨텍스트가 허용하는 범위에서 이전 첨부 파일도 함께 모델에 보내고, 들어가지 않는 파일은 이름만 모델에 알려 줍니다. 대화 하나의 첨부 파일은 합계 48 MB 이하입니다. 대화를 삭제하면 해당 첨부 파일도 함께 삭제되며, "모델 및 서비스" 화면의 "참조되지 않은 파일 정리"도 더 이상 쓰지 않는 첨부 파일을 정리합니다
* `기능` 답변을 다시 생성하거나 메시지를 편집해 다시 보내도 이후 대화가 삭제되지 않고, 해당 차례의 새 버전이 만들어집니다: 답변 아래에 "< 2/3 >"가 표시되며 양쪽 화살표로 버전을 전환하면 이후 메시지도 함께 바뀌고, 대화를 다시 열어도 마지막으로 선택한 버전이 표시됩니다. 한 차례에는 최대 8개 버전을 둘 수 있으며, 한 대화에서 표시되지 않은 버전의 합계가 약 2MB를 넘으면 가장 오래된 버전부터 삭제됩니다. 검색, 내보내기, 읽어 주기, 사용량 집계와 대화 이어 가기에는 현재 표시된 버전만 사용되며, 버전이 여러 개인 메시지를 삭제하면 현재 표시된 버전만 삭제됩니다. 1.6.0 이하로 되돌리면 그때 표시하던 버전만 보이며, 이전 버전 앱에서 채팅 화면을 여는 즉시 모든 대화의 다른 버전이 삭제되고 다시 업그레이드해도 복구되지 않습니다
* `수정` 긴 대화에서는 이전 내용을 자동으로 요약해 컨텍스트를 절약하지만, 일부 온라인 서비스와 로컬 모델이 돌려주는 요약에 Markdown 코드 블록 기호나 설명 문구가 붙어 요약이 실패하고 모델이 이전 대화 내용을 잊기 쉬웠던 문제; 이제 이런 기호와 설명을 먼저 제거한 뒤 요약을 읽습니다
* `수정` 로컬 모델을 삭제해도 처음 불러올 때 만들어진 캐시 파일 (모델마다 수 GB에 이를 수 있음)이 앱 캐시에 남아 저장 공간을 계속 차지하던 문제; 이제 로컬 모델을 삭제하면 이 캐시도 함께 삭제합니다. 이전에 삭제한 모델이 남긴 캐시는 다음에 이 플러그인을 열 때 자동으로 정리되며, "모델 및 서비스" 화면의 "참조되지 않은 파일 정리"로도 정리할 수 있습니다. 남아 있는 로컬 모델의 캐시에는 영향이 없습니다
* `개선` 설정 화면을 정리했습니다: 홈에는 모양 설정과 "대화", "모델 및 서비스", "음성", "개인정보 및 권한", "업데이트 및 정보" 5개 항목만 남기고, 각 설정은 한 곳에만 표시됩니다. "대화"의 "생성"은 "출력 길이 및 sampling"으로 이름이 바뀌었고, 편집 중에 아래로 스와이프하거나 양식 바깥을 탭해도 닫히지 않으며, 저장하지 않은 변경 사항이 있으면 먼저 확인합니다. 버전 기록은 "업데이트 및 정보"로 옮겼습니다. 채팅 화면의 메뉴와 사이드 드로어에서 별도의 "모델" 항목을 없애고 "설정"에서 들어가도록 했습니다. AutoJs6에서 이 플러그인의 설정을 열면 바로 "모델 및 서비스"가 열리고, 뒤로 키를 누르면 설정 홈으로 돌아갑니다
* `개선` 기존의 "모델" 화면과 "온라인 서비스" 화면을 "모델 및 서비스" 화면 하나로 합쳤습니다: 맨 위에 기본 대상과 "모바일 및 종량제 네트워크 허용"이 있고, 그 아래에 "온라인 서비스"와 "로컬 모델" 두 섹션이 있습니다. 모든 서비스와 로컬 모델은 같은 모양의 카드로 표시되며 "기본", "준비됨", "API key 없음", "사용 불가" 라벨이 붙습니다. 기본값으로 설정, 테스트, 이름 변경, 복제, API 키 지우기, 삭제 등은 카드 오른쪽 메뉴에, 서비스 가져오기 / 내보내기, 사전 설정 모델 새로 고침, 참조되지 않은 파일 정리 등은 섹션 제목 오른쪽 메뉴에 있습니다. 로컬 모델을 탭하면 세부 정보를 보고 모델 ID를 복사할 수 있습니다. 온라인 프로필은 "서비스"라는 이름으로 통일했습니다
* `개선` 기존의 "기본 온라인 대상"과 로컬 모델의 "선택"을 하나의 "기본 대상"으로 합쳤습니다. 온라인 모델이나 로컬 모델 중 무엇이든 지정할 수 있으며, 새 대화와 모델을 지정하지 않은 스크립트가 이를 사용합니다. 업그레이드 후에도 이전의 기본 설정을 그대로 이어받습니다. 기본 대상을 잠시 사용할 수 없을 때 (예: API 키를 지운 경우) 자동으로 다른 사용 가능한 모델을 쓰고, 다시 사용할 수 있게 되면 원래대로 돌아갑니다. 기본 대상의 서비스나 모델을 삭제한 경우에도 자동으로 다른 사용 가능한 모델을 씁니다. 서비스의 "기본 모델"은 "우선 모델"로 이름이 바뀌었습니다
* `개선` 서비스는 이제 기존의 아래에서 올라오는 양식 대신 전체 화면의 "서비스 세부정보" 페이지에서 추가하고 편집합니다: 위쪽에는 서비스 이름, 제공자, Base URL, API 키 등 연결 정보가 있고, 아래쪽에는 "모델 목록"이 있습니다. 행을 길게 누르거나 핸들을 끌어 순서를 바꿀 수 있고, 각 행의 메뉴에서 우선 모델로 설정, "이미지 입력" 표시, 위아래로 이동, 제거를 할 수 있으며, 여러 모델을 한 번에 추가할 수도 있습니다. 이에 따라 기존의 "모델 ID", "기본 모델", "이미지 입력 모델" 선택기 3개는 없어졌습니다. 오른쪽 위의 체크 표시를 눌러 저장하고, 저장한 뒤에는 같은 페이지에서 연결을 테스트할 수 있습니다. 저장하지 않은 변경이 있을 때 뒤로 가면 먼저 확인하며, 화면을 회전하거나 백그라운드에서 시스템이 앱을 회수해도 입력한 내용이 유지됩니다. 순서를 바꾼 뒤에도 기본 대상과 즐겨찾기는 원래 모델을 그대로 가리킵니다
* `개선` 추천 로컬 모델 다운로드가 한 단계로 바뀌었습니다: 확인하면 앱의 비공개 저장소에 바로 다운로드되고 검증되면 자동으로 가져옵니다. 먼저 "저장 위치 선택"을 하고 다운로드가 끝난 뒤 "다운로드한 모델 가져오기"를 누를 필요가 없습니다. 다운로드하는 동안 "모델 및 서비스" 페이지에 다운로드 카드가 표시되어 일시중지, 계속, 취소를 할 수 있고 실패하면 다시 시도할 수 있습니다. 네트워크가 끊기거나 앱이 종료되어도 다운로드된 부분은 유지되며, 계속하거나 다시 시도하면 중단된 지점부터 이어서 받습니다. 다운로드 확인 창에는 모델의 최소 메모리가 표시되고, 이 기기의 메모리가 부족하면 경고하지만 다운로드는 할 수 있습니다. 이전에 다른 위치에 다운로드한 모델 파일은 계속 "모델 파일 가져오기"로 추가할 수 있습니다. 다운로드한 모델은 앱 데이터에 저장되며, 앱 데이터를 지우거나 앱을 제거하면 함께 삭제됩니다
* `개선` 모델 전환 패널에서 각 모델이 한 번만 표시됩니다: 즐겨찾기한 모델은 맨 위 "즐겨찾기" 그룹에만 표시되고 소속 서비스 아래에 중복으로 나타나지 않으며, 즐겨찾기를 해제하면 원래 위치로 돌아갑니다. 검색 결과는 그룹으로 나누지 않고 원래 순서대로 하나의 목록으로 표시합니다. 각 행 아래에 소속 서비스를 표시하고, 로컬 모델은 파일 크기를 표시합니다. "이 기기" 그룹의 이름이 "로컬 모델"로 바뀌었습니다

# v1.6.0

###### 2026/11/12

* `기능` 온라인 프로필에서 기본 추론 강도 (낮음, 보통, 높음, 매우 높음, 최대; "기본"이면 모델이 결정)를 설정할 수 있고, Anthropic 프로필은 기본으로 빠른 모드 (답변이 빨라지는 대신 요금이 높음)를 쓸 수 있습니다; 채팅 중 현재 대화에만 적용되도록 바꿀 수도 있으며, 바꾼 값은 대화와 함께 저장되고 새 대화는 프로필의 기본값에서 시작합니다. 모델이 선택한 단계를 지원하지 않으면 가장 가까운 낮은 단계를 사용합니다
* `기능` 모델 전환이 아래에서 열리는 패널로 바뀌었습니다: 검색, 프로필별 그룹, 자주 쓰는 모델 즐겨찾기와 맨 위 고정, 이미지 입력, 추론, 빠른 모드 지원 여부 표시; 패널에서 현재 대화의 추론 강도와 빠른 모드를 바로 바꿀 수 있고, 아래쪽 "모델 및 서비스 관리"로 모델 설정을 열 수 있습니다. 채팅 화면 위쪽에 현재 대화의 추론 강도와 빠른 모드가 표시됩니다
* `기능` 채팅에서 모델의 생각 과정을 볼 수 있습니다 (Claude 5 이상, Gemini 2.5 이상, 그리고 DeepSeek 처럼 생각 내용을 돌려주는 OpenAI 호환 서비스 지원): 답변을 생성하는 동안 답변 위의 카드에 생각 내용이 실시간으로 표시되고, 완료되면 "N초 동안 생각함" 한 줄로 접히며 탭하면 펼치거나 접을 수 있습니다. 생각 내용은 대화와 함께 저장되지만 소리 내어 읽지 않으며 메시지 검색에도 걸리지 않습니다. 설정의 "생성 중 생각 내용 표시" 와 "완료 후 자동으로 접기" 는 기본으로 켜져 있으며 필요하면 끌 수 있습니다. 스크립트가 플러그인을 통해 AI 를 호출할 때는 생각 내용을 돌려주지 않습니다
* `수정` 화면 회전, 다크 모드 전환, 언어나 메시지 글꼴 크기 변경 시 생성 중인 답변이 중지되던 문제; 이제 답변이 계속 생성되며, 채팅 화면을 벗어나 있는 동안 생성이 끝난 답변도 돌아오면 전체가 표시됩니다
* `수정` "중지"를 눌러도 온라인 요청이 바로 끊기지 않고 답변 생성이 끝날 때까지 백그라운드에서 계속되던 문제 (사용량에도 계산됨); 이제 중지를 누르면 1초 안에 요청을 끊으며, 새 대화, 대화 전환, 모델 전환, 메시지 삭제 시에도 마찬가지입니다
* `수정` Anthropic 프로필에 온도, Top K, Top P를 설정하면 최신 Claude 모델이 요청을 거부하던 문제; 이제 Anthropic 프로필은 이 세 항목을 보내지 않으며 설정 화면에도 안내합니다
* `수정` 프로필의 기본 모델을 바꿔도 이미 열려 있고 아직 메시지가 없는 새 대화는 이전 기본 모델을 계속 쓰던 문제; 이제 새 기본 모델로 바뀝니다 (그 대화에서 다른 모델을 직접 고른 경우 제외)
* `수정` 온라인 프로필을 추가하거나 편집할 때 양식에서 아래로 스와이프하면 양식이 쉽게 닫혀 입력한 내용이 모두 사라지던 문제; 이제 양식은 오른쪽 위의 닫기 버튼, "취소" 또는 뒤로 키로만 닫히고, 저장하지 않은 변경사항이 있으면 먼저 확인하며, 화면을 회전해도 입력한 내용이 유지됩니다
* `수정` Gemini 공식 문서 이전과 표 형식 변경으로 온라인 모델 카탈로그 자동 업데이트가 실패하는 문제

* `수정` AI 서비스가 이전 세션을 닫기 전에 종료되면 다음 요청이 실패하는 문제
* `수정` 취소한 모델 세션이 종료되는 동안 다음 AI 요청이 거부되는 문제
* `수정` Anthropic 공식 API 는 최대 출력 토큰을 제한 없음으로 두어도 항상 max_tokens=1024 로 요청하여 응답이 약 1024 토큰에서 아무 표시 없이 잘렸습니다 (기본으로 사고하는 Claude 모델은 사고 분량도 여기에 포함됩니다); 기본값을 16384 토큰으로 올리고, 출력 한도에서 끊긴 응답은 메시지 아래에 "출력 한도에 도달했습니다" 로 표시합니다 (OpenAI 호환 API 와 Gemini 도 동일)
* `수정` 연결 테스트가 모델 출력을 8 토큰으로 제한하여, 기본으로 사고하는 Claude 모델이 이를 사고에 모두 써 버려 텍스트를 반환하지 못했고, 올바르게 설정한 Anthropic 프로필이 잘못된 응답으로 판정되었습니다; 이제 1024 토큰까지 허용합니다
* `수정` 클라우드 생성이나 연결 테스트가 실패했을 때 고정된 실패 범주만 표시되어 실제 원인 (예: 계정 잔액 부족) 을 알 수 없었습니다; 이제 실패 메시지 아래에 HTTP 상태와 제공자가 보낸 설명 (최대 300 자, 키는 가림) 을 표시합니다

### 빌드

******

```powershell
.\gradlew.bat :app:assembleDebug
```

릴리스 빌드:

```powershell
.\gradlew.bat :app:assembleRelease
```

빌드 매개변수는 `version.properties`에서 가져옵니다. 현재 최소 SDK는 24, 대상 SDK는 36이고 JDK 21 이상이 필요합니다.

프로토콜 ABI는 `libs`의 저장소 로컬 AAR에서 제공됩니다:

```text
common-plugin-api.aar
protocol-wire-api.aar
ai-common-api.aar
ai-provider-api.aar
```

Runtime은 Maven의 LiteRT-LM 0.15.0을 사용합니다. 릴리스 빌드는 LiteRT-LM runtime 클래스를 유지하고 ABI APK 2개와 universal APK 1개를 만듭니다.

******

### 라이선스

******

프로젝트 소스는 MPL-2.0으로 배포됩니다. LiteRT-LM 및 기타 타사 구성 요소에는 각각의 라이선스가 계속 적용됩니다.

******

### 리소스 구성

******

```text
.readme/lang_*.json
.changelog/lang_*.json
.python/generate_markdown.py
app/src/main/assets/doc/CHANGELOG-*.md
app/src/main/res/values-*/strings.xml
```

`.python/generate_markdown.py`는 JSON 소스에서 10개 언어 README와 앱 내 changelog를 생성합니다. Android 문자열은 각 리소스 디렉터리에서 관리합니다.
