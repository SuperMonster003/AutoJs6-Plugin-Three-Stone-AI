### 概要

******

3-Stone AI は AutoJs6 の公式 AI テキスト生成プラグインです. ユーザーがインポートした LiteRT-LM モデルを明示選択した CPU または互換 GPU backend 上で実行し, オンライン生成にはユーザーが設定したオンラインサービスを使用します. ローカルとオンラインの実行先は 1 つの AI Provider V2 target catalog, 制御されたストリーミングパイプライン, 明示選択境界を共有します. ローカルターゲットはネットワークアクセスもデータ送信も行わず, オンラインターゲットはユーザーが明示選択した場合のみ, プラグイン管理の認証情報と宣言済み HTTPS origin に固定して実行されます.

******

### 機能

******

- Android システムピッカーから `.litertlm` モデルパッケージをインポートし, 検証済みコピーをアプリ専用ストレージに保存します.
- 内蔵カタログから固定バージョンで認証不要の LiteRT Community 推奨モデルを 1 ステップでダウンロードします: アプリ専用ストレージへ直接書き込み, 正確なサイズと SHA-256 を検証してから自動でインポートします. ダウンロード中のモデルは "ローカルモデル" セクションにカードとして表示され, 進捗, 一時停止, キャンセル, 失敗時の再試行に対応し, 中断しても受信済みの部分から再開します. ダウンロードの確認画面にはモデルの最低メモリ要件を表示し, 端末のメモリが足りない場合は注意を表示します.
- システムピッカーを開く前にプライベートストレージを事前確認し, 現在のインポート予算とプライベートコピーの推定使用量を表示し, コピー前に選択ファイルを再確認します.
- プレーンテキストの system, user, assistant 履歴からローカル生成リクエストを作成します.
- AutoJs6 の `ai.ask`, `ai.chat`, `ai.stream` から `temperature`, `topK`, `topP`, `maxTokens` を LiteRT-LM まで渡します.
- AutoJs6 の `structuredJson` と `responseSchema` により LiteRT-LM ネイティブ JSON Schema 制約デコードを使用し, 完成した値は `JSON.parse` 用の JSON テキストとして返します.
- LiteRT-LM の正確な入力, 出力, 合計 token 数とプロバイダー側の生成時間を, AutoJs6 の `ai.chat().usage` とストリーム usage イベントで返します.
- AutoJs6 の `ai.session` で 1 つの LiteRT-LM ネイティブ Conversation に複数ターンのコンテキストを保持し, 2 ターン目以降は新しいユーザープロンプトだけを送信します.
- モデルの SHA-256 をキーに初期化済み Engine を再利用し, 同じモデルへの連続リクエストで繰り返すコールドスタートをなくします.
- インポートした各モデルを任意で一度初期化し, "利用可能/互換性なし"の状態を保存して, モデル管理画面から再チェックできます.
- credit バックプレッシャーでテキスト chunk を順番に配信し, 完了, 失敗, キャンセルのいずれか 1 つの終端状態だけを公開します.
- "ローカルモデル" セクションでインポート済みモデルの一覧表示, 名前変更, チェック, 削除を行い, 各カードにモデルの使用容量を表示します. モデルを削除すると, 初回読み込み時に作られた LiteRT-LM エンジンのキャッシュも削除します. "未参照ファイルをクリーンアップ" で未参照のモデルファイル, 残ったエンジンキャッシュ, 使われなくなった添付ファイルを回収できます.
- AutoJs6 から `cpu`, `gpu`, `npu` backend を明示選択できます. CPU が既定で, GPU は OpenCL 読み込み検査の成功時だけ公開し, NPU は EAP runtime 未同梱のため利用不可と明示します.
- 設定 > モデルとサービス で, 組み込みおよびカスタムのオンラインサービス, Android Keystore 認証情報, 1 つだけの既定のターゲット (オンラインモデルでもローカルモデルでも可), 従量制ネットワーク, 明示的で上限付きの接続テストを管理します. サービスは全画面の "サービスの詳細" 画面で編集します: サービスごとに複数のモデルを追加し, ドラッグで並べ替えて優先モデルを設定でき, チェックマークを押したときだけ保存されます.
- サービスの詳細画面の "リクエストヘッダー" で, サービスごとに最大 16 件のカスタムリクエストヘッダーを設定できます. 値の指定方法は固定値, 秘密値, "会話ごとに自動生成" (サービスと会話から導出され, 同じ会話の中では変わりません) です. OpenCode Go セッション, OpenRouter の帰属表示, Helicone, Cloudflare AI Gateway のプリセットがあり, サービスのアドレスが opencode.ai でセッションヘッダーがない場合や, サービスが MissingSessionID を返した場合は追加の入口を表示します. プラグイン自身が送信するヘッダーと HTTP 接続が管理するヘッダーはカスタマイズできません. User-Agent は既定値を置き換え, anthropic-beta はプラグインの値と結合されます. リクエストヘッダーはサービスの設定とともに自動で適用され, スクリプトには公開しません.
- 各ランチャー会話をローカルまたはオンラインターゲットのスナップショットへ固定します. メッセージのある会話で変更すると新規会話を推奨し, 続行には明示確認と変更記録が必要です.
- 各アシスタント応答に実際の target/provider/model/locality スナップショットを保存します. 再生成は記録された元のターゲットを厳密に再利用し, ID 情報の変更や利用不可時には明示的に失敗し, 現在の会話ターゲットへ暗黙にフォールバックしません.
- ローカルとクラウドの生成失敗を選択済みの境界内に維持します. ランチャーチャットは機密情報を含まない限定的な失敗理由を追記し, 境界をまたぐ自動フォールバックがなかったことを明示し, 部分出力を保持したまま手動ターゲット切り替えを提供します.
- オンラインの OpenAI 互換, Anthropic Messages, Gemini GenerateContent でネイティブツール呼び出しに対応. ストリーミング引数, 並列呼び出し, 結果送信後の継続をサポート.
- モデルごとの設定と協商した AI Provider 2.1 によるオンライン JPEG/PNG 入力および画像付きツール結果.
- GitHub のプロジェクトが公開するカタログからオンラインのプリセットモデルを更新できます. 自動更新は既定で有効で, "モデルとサービス" 画面を開く際に 24 時間に 1 回確認します. "オンラインサービス" セクションのメニューから自動更新をオフにしたり手動で更新したりできます. 従量制ネットワークの設定に従い, オフライン時や更新失敗時もキャッシュまたは内蔵の一覧を利用できます. 保存済みのサービスとカスタムモデル ID は変更しません.
- プリセットモデルを提供元ごとに分類し, OpenRouter の選択肢を Qwen, Kimi, GLM, Grok, Meta, MiniMax などに拡充します. 正確なモデル ID は維持します.
- 独立設定を平面グループ, 統一した行と中央の角丸ダイアログに統一しました. 言語, 夜間モード, テーマ色, ランチャーアイコンは確定後に適用され, キャンセルでは保存値を変えません. 色は既定で AutoJs6 に従い, 共通パレット, HEX/RGB 入力と局所プレビューを提供します. 中立な背景色は固定し, コントロールは選択したテーマに従います. ランチャーの既定は自動適応で, 更新時には明示的な選択を保持します.
- 設定のホームには外観の設定と "会話", "モデルとサービス", "音声", "プライバシーと権限", "更新とアプリ情報" の 5 つの入口だけを置き, 各設定は 1 か所にだけ表示されます. バージョン履歴は "更新とアプリ情報" にあります. チャット画面のメニューとサイドドロワーからは "設定" 経由でモデルの設定に進みます. AutoJs6 からこのプラグインの設定を開くと "モデルとサービス" が直接開き, 戻るキーで設定のホームに戻ります.
- チャットの返答の生成はチャット画面から独立しました: 画面の回転, ダークモードの切り替え, 言語やメッセージの文字サイズの変更でも生成が続き, チャット画面を離れている間に終わった返答も戻ったときに全文が表示されます (システムがアプリのプロセスを終了した場合は中断されます). "停止" のタップ, 新しい会話の作成, 会話やモデルの切り替え, メッセージの削除では 1 秒以内にオンラインのリクエストを切断し, 停止後に使用量が増えることはありません.
- オンラインサービスで既定の推論強度 (既定, 低, 中, 高, 超高, 最大; "既定" ではモデルに任せます) を設定でき, Anthropic のサービスでは高速モード (返答が速くなる代わりに料金が高くなります) を既定でオンにできます; チャット中に現在の会話だけを変更でき, 変更は会話と一緒に保存されます. モデルが選んだ段階に対応していない場合は, いちばん近い下の段階が使われます. スクリプトがプラグインのインターフェース経由で AI を呼び出す場合, この 2 項目は使われません.
- モデルの切り替えは下から開くパネルで行います: お気に入りのモデルは上部の "お気に入り" グループに, それ以外はサービスごとのグループに表示され, 各モデルは 1 回だけ表示されます; 検索結果はグループに分けません; 各行の下に所属するサービス (ローカルモデルはファイルサイズ) を表示し, 画像入力, 推論, 高速モードも表示します; パネルから現在の会話の推論強度と高速モードを直接変更でき, 下部の "モデルとサービスを管理" からモデル設定を開けます. チャット画面上部に現在の会話の推論強度と高速モードが表示されます.
- モデルの思考過程を表示します (Claude 5 以降, Gemini 2.5 以降, および DeepSeek など思考内容を返す OpenAI 互換サービス): 生成中は返答の上のカードに思考内容がリアルタイムで表示され, 完了すると "N 秒間思考しました" に折りたたまれ, タップで開閉できます. 設定の "生成中に思考内容を表示" と "完了後に自動で折りたたむ" は既定でオンです. 思考内容は会話と一緒に保存されますが, 読み上げ, メッセージ検索, コピーの対象にならず, スクリプトにも返されません.
- 入力欄の左にある "+" をタップして添付ファイルを追加できます (1 件のメッセージにつき最大 20 個). 画像はシステムの写真選択ツールで選び (大きすぎる画像は自動的に縮小), "画像入力" がオンのモデルに送ります. UTF-8 のテキストファイル (txt, md, json, csv やコードファイルなど) はテキストとして送り, PDF はプロバイダーが Anthropic または Gemini のサービスに送ります. ローカルモデルではまだ添付ファイルを使えず, 現在のモデルが対応していない添付ファイルは薄く表示されて送信できません. 添付ファイルはメッセージと一緒に保存され, メッセージにはサムネイルかファイル名が表示され, タップすると他のアプリで開けます. 以降のターンではコンテキストに収まる範囲で以前の添付ファイルも再送し, 収まらないものはファイル名だけをモデルに伝えます.
- 返答を再生成したり, メッセージを編集して再送信したりすると, その後の会話を削除せず, そのターンの新しいバージョンを作ります. 返答の下の "< 2/3 >" でバージョンを切り替えるとその後のメッセージも切り替わり, 会話を開き直しても前回選んだバージョンが表示されます. 検索, エクスポート, 読み上げ, 使用量の集計, 会話の続きには表示中のバージョンだけを使います.
- 会話を "Markdown でエクスポート" (保存場所はシステムの保存ダイアログで選び, 他の Markdown リーダーでも正しく表示されます) または "画像として共有" (チャット画面の見た目で長い画像を作り, システムの共有パネルで共有) できます. チャット画面のメニュー, またはサイドドロワーで会話を長押ししたときのメニューから選びます. エクスポートされるのは表示中のバージョンだけで, 思考内容がある会話では含めるかどうかを先に確認し, 既定では含めません.
- 会話履歴は v6 形式になり, 会話ごとの推論強度と高速モード, 返答ごとの思考内容と思考時間, さらにメッセージの添付ファイル情報とほかのバージョンも保存します. 1.5.0 以前に保存した会話も引き続き開けます. 1.6.0 以前に戻すと, その時点で表示していたバージョンしか見られません. 旧バージョンでチャット画面を開いた時点ですべての会話のほかのバージョンが破棄され, 再びアップグレードしても元に戻せません.
- 入力欄内のマイク: タップして話すと, 認識された文字がカーソル位置に入り, 確認してから送信できます. 長押しすると音声会話になり, 話した内容をすぐ送信し, 応答を読み終えると再び聞き取ります.
- 応答の読み上げ: 応答を長押しして "読み上げ" を選ぶか, 設定 > 音声 で "応答を自動で読み上げ" をオンにすると, 新しい応答を生成しながら読み上げます. 見出しやリストの記号は読まず, コードブロックと表はそれぞれ一文で知らせます.
- 3-Macaw Speech のデジタルアシスタントの `VOICE_COMMAND` に応答: 電源ボタンを長押しして話し, "3-Stone AI" をタップすると, 新しい会話で質問をすぐ送信し, 回答を読み上げます.

### 音声

******

音声入力と読み上げには Android のシステムインターフェース (`RecognizerIntent` と `TextToSpeech`) を使います. 3-Stone AI 自身は録音せず, マイクの権限も求めません. 3-Macaw Speech がインストールされている場合, 設定 > 音声 の "3-Macaw Speech を優先" は既定でオンになり, 音声入力はそのオフライン認識シートを開き, 読み上げはそのオフライン音声を使います. インストールされていない場合やオプションをオフにした場合は, 端末にある認識アプリと既定の音声合成エンジンを使います. 1.4.0 の音声会話では毎回認識画面が開きます. 応答の読み上げ中に入力欄の上のステータスバーをタップすると中断してすぐ次を話せます. ステータスバーのボタンで終了できます.

- **音声認識アプリが複数あり, 毎回選択を求められる?** "3-Macaw Speech を優先" をオンのままにすると 3-Macaw Speech を直接使います. オフにするとシステムが決め, システムの選択画面で既定のアプリを設定できます.
- **性能の低い端末で文と文の間に間が空く?** 一部の音声 (MeloTTS, Kokoro など) は遅い端末では読み上げより合成が遅くなります. 3-Macaw Speech で既定の音声を AISHELL-3, Piper, Matcha のいずれかにしてください.
- **マイクをタップすると認識モデルがないと表示される?** 3-Macaw Speech の認識シートがモデルのダウンロードを案内します. それまで 3-Stone AI が自動で他の認識アプリに切り替えることはありません. 一時的に他のアプリを使うには "3-Macaw Speech を優先" をオフにしてください.
- **3-Macaw Speech のデジタルアシスタントから質問するには?** 3-Macaw Speech を既定のデジタルアシスタントに設定し, 電源ボタン (またはホームボタン) を長押しして話し, 結果カードの "3-Stone AI" をタップします. 3-Stone AI は新しい会話を開き, 質問をすぐ送信して回答を読み上げます. ロック中は先にロックを解除してください. 前回の同様の質問から 10 秒以内の場合, 文字は入力欄に入るだけで送信されません.
- **認識された文字はどこへ送られる?** 入力した文字と同じく選択中のモデルへ送られます. オンラインモデルではプロバイダーに送信されます. 3-Macaw Speech は完全にオフラインで動作し, その他の認識アプリや読み上げアプリはネットワークを使う場合があります.

### モデルとデータ形式

******

対応するモデルと入力形式:

```text
model package: .litertlm
input: text/plain history + application/json schema; negotiated 2.1: image/jpeg and image/png descriptors
output: streamed text/plain or application/json text chunks
runtime: LiteRT-LM 0.15.0
```

******

### プラグインインターフェース

******

ホストは次の識別情報でプラグインを検出して呼び出します:

```text
service action: org.autojs.plugin.AI_PROVIDER
plugin id: three-stone-ai
protocol provider id: autojs6.three-stone-ai
engine: three-stone-ai
variant: default
protocol: V2 (2.0 / 2.1)
required host build: 5276
```

AI Provider V2 は `local:*` と `profile:*` ターゲットを 1 つのページ化 catalog で公開します. 各ターゲットは provider, model, locality, 設定/可用性, capabilities, limits, controls, HTTPS origins を個別に宣言します. ローカル専用 catalog は ON_DEVICE/NONE を宣言し, online profile が存在する場合は HYBRID/PLUGIN_MANAGED と HTTPS origins の正確な和集合を宣言します. ローカル backend profile は任意の target control であり, 使用不可 profile やターゲットへ暗黙にフォールバックしません.

ホスト build 5276 以降と Android 7.0 以降が必要です. ビルド出力には armeabi-v7a, arm64-v8a, x86, x86_64, universal APK が含まれます. x86 と armeabi-v7a 端末では対応する個別 APK を使用してください. アプリ画面, オンライン AI, ホスト連携に対応します. LiteRT-LM のローカル推論には arm64-v8a または x86_64 と APK 内の対応ネイティブライブラリが必要です. universal APK は 64 ビットライブラリのみを含み, 32 ビット専用端末にはインストールできません.

### ホスト統合状態

******

> AutoJs6 (build 5276 以降) では, `ai.catalog()` がインポート済みローカルモデルと設定済みオンライン profile を統一ターゲットカタログとして返し, 正確な ID, プロバイダー, モデル, ローカリティ, 設定/可用状態, 機能, 制御項目, 上限, オリジン, ローカル backend profile を含みます. `ai.ask`, `ai.chat`, `ai.stream`, `ai.session` に正確な `target` を渡します. `target` だけなら公式 3-Stone AI プラグインを選択し, `plugin: true` は宣言済みデフォルトターゲットを使います. ローカルターゲットは `cpu`, `gpu`, 利用不可の `npu` を公開できますが, オンラインターゲットにローカル実行 profile はありません. backend またはターゲットが利用不可ならフォールバックせず失敗し, ローカル/オンラインルートも自動切替しません. 完了/ストリーム応答は target, plugin, profile, reasoning, finish reason, 完全な usage, プロバイダー計測時間を公開します. 安定したエラーはプロバイダー欠落/無効, ターゲット不明/未設定/利用不可/機能不一致, backend 利用不可を区別します. `responseSchema` は構造化出力を有効にし, schema なしの `structuredJson: true` は既定の object ルートを使い, 永続セッションは全ターンで同じ target, schema, 任意 backend を固定します.

独立署名アプリがプラグインで AI アクセスを要求可能, アプリとインストールの識別情報に許可を結び付け, 設定で取り消すと実行中のリクエストも停止. この許可はローカルモデルと保存済みオンラインアカウントを対象とし, オンライン呼び出しは有料枠を消費する場合があります. Node.js, Bun と Worker では ai.hasAccess() と ai.requestAccess() を使います.

### セキュリティとプライバシー

******

ユーザーが開始する推奨モデルのダウンロード, ユーザー設定済みオンラインターゲットへのリクエスト, "モデルとサービス" 画面での GitHub 公開プリセットカタログの更新に `INTERNET` 権限を使用します. カタログ更新に API キーは不要で, 推論を呼び出さず, プラグインの有効化やローカル生成時には開始しません. 広範なストレージ権限は要求しません. モデルファイルのダウンロードは不変 HTTPS リビジョン, 固定サイズと SHA-256 を使い, アプリ専用の `files/model-downloads` 内の部分ファイルだけへ書き込みます (中断後は自動で再試行し, 続きから再開します); LiteRT-LM ヘッダー, サイズ, ダイジェスト, flush, fsync がすべて成功してから `files/models` に移してインポート処理に渡し, アトミックに有効化します. インポートは引き続きピッカー URI のみを読み, 検証済みコピーを `files/models` に書いて原子的に有効化します. 元のホスト用 Provider は AutoJs6 パッケージ, UID, 署名, target metadata, 宣言済み origin 境界も検証します. 音声機能はマイクの権限を求めず, 録音は認識アプリが行います. 認識した文字と読み上げる文字はログに記録せず, 音声入力したメッセージは入力したメッセージと同じく保存されます. モデルが返した思考内容は端末内の会話履歴にのみ保存され, 以降のターンでオンラインサービスに送り返されることはなく, プラグインのインターフェース経由でスクリプトに返されることもありません. チャットの添付ファイルはシステムのピッカーで読み取るため, ストレージや写真の権限は要りません. 選んだファイルはアプリ専用の `files/attachments` にコピーされ, 選択したオンラインモデルのサービスにのみ送信され, 会話を削除すると一緒に削除されます. 添付ファイルを他のアプリで開くときは, `files/attachments` だけを公開する FileProvider を通じて一時的な読み取り権限を付与します. 共有する長い画像はアプリのキャッシュ `cache/share` に書き込み, このディレクトリだけを公開する別の FileProvider で共有パネルに渡します. 新しい画像を作る前に 24 時間を超えた画像を削除し, 最大 3 枚まで保持します. エクスポートした Markdown は, システムの保存ダイアログで選んだ場所にのみ書き込みます. サービスのカスタムリクエストヘッダーのうち秘密値は, API キーと同じく Android Keystore で暗号化して端末内に保存し, 画面に再表示せず, エクスポートにも含めません. インポート, 複製, プロバイダーまたは HTTPS オリジンの変更の後は入力し直す必要があります. プロバイダーのエラー詳細に現れた API キーと秘密値は `[redacted]` に置き換えます. 固定値は平文で保存されエクスポートにも含まれるため, キーを固定値として入力しないでください.

### 動作制限

******

- モデルのインポートには 8 GiB の厳格な上限があり, 完了後に 256 MiB 以上の空き容量が必要です.
- 未完了のモデルダウンロードは 1 件だけ保持され, 別のモデルのダウンロードを始めると破棄されます (確認画面に明記されます). ダウンロードは AutoJs6 公式プラグイン共通のダウンロードライブラリがアプリ専用の `files/model-downloads/<sha256>/model.litertlm.part` に書き込みます: ネットワークが切れたときは自動で 2 回 (約 2 秒後と 5 秒後に) 再試行し, そのたびに HTTP Range で中断した位置から続きを受信します; 一時停止, アプリの終了, プロセスの終了ではこのファイルを残し, 再開や再試行のときは受信済みの部分を検証し直してから続きを受信します; キャンセル, 無効な内容, ダイジェストの不一致では削除します. 未完了のダウンロードが古くなったことを理由に削除されることはありません. 検証済みのファイルは `files/models/.download-<sha256>.part` に移してからインポート処理に渡します. コールドスタート時は, まだインポートされていない推奨モデルの最新のダウンロードを一時停止状態に戻し, それ以外は削除します; 1.7.0 が `files/models/.download-<sha256>.part` に残した未完了のファイルは新しい場所へ移され, 受信済みのバイトから続きを受信します.
- ダウンロードまたはインポートしたローカルモデルはアプリ専用データ (`files/models`) に保存され, 使用容量は "ローカルモデル" セクションのカードとモデル切り替えパネルに表示されます. プラグインをアンインストールするか, アプリデータを消去すると, これらのモデルも削除されます; 以前に別の場所へダウンロードしたモデルファイルは "モデルファイルをインポート" で取り込めます.
- Application scope の単一インポート coordinator により Activity 再作成中も処理を継続します. Fsync 済み pending journal でコールドスタート復旧と stale な `.incoming`, `.current`, `.pending` 一時ファイルの cleanup を行います. 復旧で削除するのは現在の試行が新規作成し current metadata で一度も公開していない destination だけで, 公開済み, current, 履歴 hash 世代は保持します.
- 独立した `:provider` プロセスとのプロセス間競合を避けるため, インポート中には以前の SHA-256 hash 名モデル世代を自動削除しません. "ローカルモデル" セクションでは catalog モデルを削除し, catalog から参照されなくなった hash 名ファイルを回収できます.
- プロセス内で同時に有効な生成セッションは 1 つだけです. リクエスト記述子は非同期処理前に複製され, プロトコルの quota に従って閉じられます.
- Provider はモデル SHA-256 と backend profile の組をキーに初期化済み Engine を最大 1 つキャッシュします. 同じ組は再利用し, いずれかのキー変更, 5 分間のアイドル, または明示的なメモリ圧迫時に安全に解放します.
- モデルチェックが確認するのは, 現在のデバイスと同梱ランタイムで `Engine.initialize()` が成功することだけです. 出力品質は評価せず, デバイスまたはランタイムの変更後に再チェックできます.
- Provider が宣言するコンテキスト上限は 256 KiB, 出力上限は 64 KiB です. リクエストとモデルはさらに低い上限を設定できます.
- 応答 schema は 64 KiB 以下の JSON object である必要があります. 対応 keyword は同梱 LiteRT-LM/LLGuidance ランタイムの実装に従います. 完成出力は厳密に parse と検証を行うため, JSON 値全体に十分な `maxTokens` を確保してください.
- `maxTokens` は 1 から 2,147,483,647 までの整数です. 省略すると出力 token 数は model/engine の既定値に委ねられますが, provider の 64 KiB 出力安全上限は維持されます. `temperature` は有限かつ 0 以上, `topK` は正の整数, `topP` は 0 から 1 の有限値である必要があります. 3 つの sampling 設定をすべて省略すると model/engine の既定値を維持し, 一部だけ指定すると未指定項目を LiteRT-LM baseline の `topK: 1`, `topP: 0.95`, `temperature: 1` で補完します.
- ストリーミングは有限の credit と制限付き chunk を使い, 無制限なバッファやバックプレッシャーなしの callback を防ぎます.
- Usage token 数は LiteRT-LM Conversation の KV cache と decode カウンターから直接取得し, 文字数による推定は行いません. `durationMillis` はプラグイン生成呼び出しのみを測定し, ホストの探索, バインド, モデル列挙, ディスパッチ時間を含みません.
- 永続的な `ai.session` は 1 つのアクティブターンだけを許可し, 正常完了後もネイティブ Conversation を保持します. キャンセル, timeout, 生成失敗, 明示的な終了の後は再作成が必要です.
- キャンセル, セッション終了, timeout は結果公開を停止し, 1 つの終端状態でリクエストを終了します.
- 設定 > モデルとサービス でサービスの "サービスの詳細" を開き, モデル一覧で画像入力に対応するモデルの行メニューから "画像入力" をオンにします. 既存のサービスでは既定で無効です. 画像はそのサービスにのみ送信されます. LiteRT と永続 ai.session は引き続きテキストのみです. Agent の画面撮影には Android 11+, 対応する AutoJs6 と AI Agent, observe グループ, 選択した正確なモデルの画像入力有効化が必要です.
- 添付ファイルの上限: 画像 1 枚 5 MB, テキストファイル 256 KB (有効な UTF-8 であること), PDF 32 MB かつ 100 ページまで (暗号化された PDF は受け付けません), 1 件のメッセージにつき 20 個, 1 つの会話で合計 48 MB. 1 回のリクエストで送る添付ファイルの元のバイト数は Anthropic と OpenAI 互換サービスが 32 MB, Gemini が 20 MB です. OpenAI 互換サービスは PDF を受け付けません. 選択したターゲットの上限を超えるメッセージは送信せず, 上限を表示します.
- 1 ターンのバージョンは最大 8 個です. 1 つの会話で表示されていないバージョンの合計が約 2 MiB を超えると, 古いバージョンから破棄します. 複数のバージョンがあるメッセージを削除すると, 表示中のバージョンだけが削除されます.
- 長い画像の高さが 16384 ピクセルを超える場合は比率を保って縮小します. メモリが不足したときは倍率を半分にして再試行し, それでも失敗した場合は Markdown でのエクスポートを案内します. 返答を生成中の会話はエクスポートできません.
- AiGoCode gpt-5.6-sol は Provider 1.2.0 / build 218 で実際の初期画像とツール結果画像の検証に合格しました. 合成画像による検証は他の対象の対応や Agent 視覚タスク全体の成功を証明しません.
- オンライン失敗は任意の `providerCode` フィールドで固定の `ONLINE_*` 分類だけを公開します. 不明な例外には分類を付けず, URL, 認証情報, サービス応答, 元の例外テキストは含めません. 失敗コードと再試行ポリシーは変更しません.
- カスタムリクエストヘッダーはサービスごとに最大 16 件です. 名前は 1 - 64 バイトの RFC 9110 token 文字のみで, 大文字と小文字を区別せず一意です. 固定値と秘密値は 1 - 1024 バイトで, 表示可能な ASCII 文字とスペースのみ使えます. すべてのリクエストヘッダーの合計は 8192 バイトまでです ("会話ごとに自動生成" は 1 件 36 バイトとして計算). プラグインが送信するヘッダーと HTTP 接続が管理するヘッダーの計 22 個はカスタマイズできず, インポート時も拒否します. 一度も値を設定していない秘密ヘッダーは送信しません. 秘密値の記録を読み取れないときはリクエスト全体を失敗させ, ヘッダーが欠けたまま送信することはありません.

******

### 宣言しない機能

******

- プラグインのインターフェースは Reasoning 出力を宣言せず, スクリプトは思考内容を受け取りません (思考過程はランチャーのチャットでのみ表示されます). ローカル LiteRT-LM は引き続き tools を宣言しません.
- ネイティブツールは最大 16 ラウンド, 同時に最大 32 呼び出しです. 結果は待機中のバッチと完全に一致する必要があります. コンテキスト/出力制限, キャンセル, 元の期限は維持されます. 永続 ai.session との併用と初期履歴の tool ロールには対応しません.
- 任意 URL からのモデルファイルのダウンロードは非対応です. プリセットモデルはプロジェクトの公開カタログから更新できますが, サービスの作成やアカウントのアクセス権の照会は行いません. ランチャーチャットと AI Provider V2 が公開するのはインポート済みローカルモデルと明示設定されたオンラインサービスのみで, ローカルモデルのダウンロード対象は固定された内蔵推奨一覧に限られます.
- NPU 推論は宣言しません. profile は `npu-runtime-not-packaged` 理由付きの `unavailable` として確認できます. GPU は `libOpenCL.so` を読み込める場合だけ宣言され, `.litertlm` 拡張子だけではモデル初期化を保証しません.

### ビルド

******

```powershell
.\gradlew.bat :app:assembleDebug
```

リリースビルド:

```powershell
.\gradlew.bat :app:assembleRelease
```

ビルド設定は `version.properties` から取得します. 現在の最小 SDK は 24, ターゲット SDK は 37 で, JDK 21 以降が必要です.

プロトコル ABI は `libs` にあるリポジトリローカル AAR から提供されます:

```text
common-plugin-api.aar
protocol-wire-api.aar
ai-common-api.aar
ai-provider-api.aar
```

Runtime は Maven の LiteRT-LM 0.15.0 を使用します. リリースビルドは LiteRT-LM runtime クラスを保持し, 2 個の ABI APK と 1 個の universal APK を生成します.

******

### ライセンス

******

プロジェクトのソースコードは MPL-2.0 です. LiteRT-LM とその他のサードパーティコンポーネントには各ライセンスが引き続き適用されます.

******

### リソース構成

******

```text
.readme/lang_*.json
.changelog/lang_*.json
.python/generate_markdown.py
app/src/main/assets/doc/CHANGELOG-*.md
app/src/main/res/values-*/strings.xml
```

`.python/generate_markdown.py` は JSON ソースから 10 言語の README とアプリ内 changelog を生成します. Android 文字列は各リソースディレクトリで管理されます.
