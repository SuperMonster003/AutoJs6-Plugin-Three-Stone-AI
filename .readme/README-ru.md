### Введение

******

3-Stone AI - официальный плагин AutoJs6 для генерации текста ИИ. Он выполняет импортированные пользователем модели LiteRT-LM на явно выбранном CPU или совместимом GPU backend и использует настроенные пользователем онлайн-сервисы для онлайн-генерации. Локальные и сетевые назначения используют единый каталог целей AI Provider V2, управляемый потоковый конвейер и явную границу выбора. Локальные цели не обращаются к сети и не отправляют данные; онлайн-цель выполняется только после явного выбора и остается привязанной к управляемым плагином учетным данным и объявленному HTTPS origin.

### Функции

******

- Импорт пакета модели `.litertlm` через системный выбор Android и хранение проверенной копии в закрытом хранилище приложения.
- Загрузка в один шаг закреплённой общедоступной рекомендуемой модели LiteRT Community из встроенного каталога: файл записывается в закрытое хранилище приложения и импортируется автоматически после точной проверки размера и SHA-256. Загружаемая модель показывается карточкой в разделе "Локальные модели" с прогрессом, паузой, отменой и повтором при ошибке, а прерванная загрузка продолжается с уже полученной части; окно подтверждения показывает минимальный объём памяти для модели и предупреждает, если у устройства меньше.
- Проверка закрытого хранилища до открытия системного выбора, отображение текущего бюджета импорта и ожидаемого размера закрытой копии, а также повторная проверка выбранного файла до копирования.
- Создание локальных запросов из истории system, user и assistant в обычном тексте.
- Передача `temperature`, `topK`, `topP` и `maxTokens` из `ai.ask`, `ai.chat` и `ai.stream` AutoJs6 в LiteRT-LM.
- Нативное ограничение вывода по JSON Schema в LiteRT-LM через `structuredJson` и `responseSchema` AutoJs6; завершенное значение остается текстом JSON для `JSON.parse`.
- Возврат точных количеств входных, выходных и общих токенов LiteRT-LM вместе с длительностью генерации провайдера через `ai.chat().usage` и потоковые события usage.
- Сохранение многоходового контекста в одном нативном Conversation LiteRT-LM через `ai.session` AutoJs6 с передачей только нового пользовательского запроса в следующих ходах.
- Повторное использование инициализированного Engine по SHA-256 модели без повторного холодного запуска для последовательных запросов к той же модели.
- При необходимости однократно инициализировать каждую импортированную модель, сохранять статус Доступна/Несовместима и повторно запускать проверку из менеджера моделей.
- Последовательная передача текстовых chunks с обратным давлением credits и публикация ровно одного конечного состояния завершения, ошибки или отмены.
- Просмотр, переименование, проверка и удаление импортированных моделей в разделе "Локальные модели", на каждой карточке указан занимаемый моделью объём; при удалении модели удаляется и кэш движка LiteRT-LM, созданный при ее первой загрузке. "Очистить файлы без ссылок" удаляет файлы моделей без ссылок, оставшиеся кэши движка и вложения, которые больше не используются.
- Явный выбор `cpu`, `gpu` или `npu` через AutoJs6: CPU используется по умолчанию, GPU доступен только после проверки загрузки OpenCL, а NPU помечается недоступным, поскольку EAP runtime не включен.
- Управление встроенными и настраиваемыми онлайн-сервисами, учетными данными Android Keystore, единственной целью по умолчанию (онлайн- или локальной моделью), тарифицируемыми сетями и явными ограниченными проверками подключения в разделе Настройки > Модели и сервисы. Сервисы редактируются на полноэкранной странице "Сведения о сервисе": в сервис можно добавить несколько моделей, менять их порядок перетаскиванием и выбрать предпочтительную, а изменения сохраняются только по галочке.
- Задавайте до 16 собственных заголовков запросов для каждого сервиса в разделе "Заголовки запросов" на странице сведений о сервисе; значение бывает постоянным, секретным или "Создается для каждого диалога" (выводится из сервиса и диалога, поэтому не меняется в пределах диалога). Есть шаблоны "Сессия OpenCode Go", "Указание источника для OpenRouter", Helicone и Cloudflare AI Gateway; если адрес сервиса находится на opencode.ai без заголовка сессии или сервис возвращает MissingSessionID, предлагается добавить его. Заголовки, которые отправляет сам плагин или которыми управляет HTTP-соединение, изменить нельзя; User-Agent заменяет значение по умолчанию, а anthropic-beta объединяется со значением плагина. Заголовки запросов применяются автоматически вместе с конфигурацией сервиса и недоступны скриптам.
- Закрепление каждого диалога launcher за снимком локальной или онлайн-цели; при смене цели заполненного диалога рекомендуется новый, а продолжение требует явного подтверждения и сохраняет запись об изменении.
- Сохранять для каждого ответа ассистента снимок фактических target/provider/model/locality; повторная генерация точно использует записанную исходную цель, явно завершается ошибкой при изменении её идентичности или недоступности и не переключается молча на текущую цель диалога.
- Сохранять ошибки локальной и облачной генерации в выбранной границе: чат лаунчера добавляет ограниченную причину без чувствительных данных, явно сообщает об отсутствии автоматического переключения между границами и предлагает ручной выбор другой цели без удаления частичного вывода.
- Нативные вызовы инструментов для онлайн-целей OpenAI-compatible, Anthropic Messages и Gemini GenerateContent, включая потоковые аргументы, параллельные вызовы и продолжение после результатов.
- Ввод JPEG/PNG и изображения в результатах инструментов через согласованный AI Provider 2.1 с настройкой для каждой модели.
- Обновлять предустановленные онлайн-модели из публичного каталога проекта на GitHub. Автообновление включено по умолчанию и проверяет каталог раз в 24 часа при открытии страницы "Модели и сервисы"; в меню раздела "Онлайн-сервисы" его можно отключить или обновить вручную. Соблюдается настройка сетей с тарификацией, без сети или при ошибке сохраняется кэшированный или встроенный список, а сохраненные сервисы и пользовательские ID не меняются.
- Сгруппировать модели по поставщикам и расширить выбор OpenRouter моделями Qwen, Kimi, GLM, Grok, Meta и MiniMax, сохраняя точные ID.
- Унифицированы плоские группы настроек, строки и скругленные диалоги по центру. Язык, ночной режим, цвет и значок меняются только после подтверждения; отмена сохраняет прежние значения. Цвет по умолчанию следует AutoJs6, доступны общая палитра, HEX/RGB и локальный предпросмотр. Нейтральный фон остается постоянным, элементы следуют теме. По умолчанию выбран автоматический адаптивный значок, обновление сохраняет явный выбор.
- На главной странице настроек остались только настройки внешнего вида и пять разделов: "Разговор", "Модели и сервисы", "Голос", "Конфиденциальность и разрешения" и "Обновления и сведения". Каждая настройка находится только в одном месте, история версий находится в разделе "Обновления и сведения". Из меню и боковой панели чата к настройкам моделей переходят через "Настройки"; если открыть настройки плагина из AutoJs6, сразу откроется "Модели и сервисы", а кнопка "Назад" вернет на главную страницу настроек.
- Генерация ответов больше не привязана к экрану чата: она продолжается при повороте экрана, смене темной темы, языка или размера текста сообщений, а ответ, завершившийся, пока вы были вне чата, показывается полностью при возвращении (если система завершит процесс приложения, ответ все же прервется). Нажатие "Остановить", создание или переключение разговора, смена модели и удаление сообщений обрывают онлайн-запрос в течение 1 секунды, и остановленный ответ больше не увеличивает расход.
- В онлайн-сервисах можно задать глубину рассуждений по умолчанию (По умолчанию, низкая, средняя, высокая, очень высокая, максимальная; при "По умолчанию" решает модель), а сервисы Anthropic могут по умолчанию включать быстрый режим (ответы быстрее, но дороже); оба параметра можно изменить только для текущего разговора, изменение сохраняется вместе с ним. Если модель не поддерживает выбранный уровень, используется ближайший более низкий. Скрипты, вызывающие ИИ через интерфейс плагина, эти два параметра не используют.
- Выбор модели открывается панелью снизу: избранные модели находятся в группе "Избранное" вверху, остальные сгруппированы по сервисам, и каждая модель показана один раз; результаты поиска не делятся на группы; под каждой строкой указан сервис (у локальных моделей размер файла) и метки ввода изображений, рассуждений и быстрого режима; на панели можно сразу изменить глубину рассуждений и быстрый режим текущего разговора, а пункт "Управление моделями и сервисами" внизу открывает настройки моделей. Полоса вверху чата показывает глубину рассуждений и быстрый режим текущего разговора.
- Показывает, как модель размышляет (Claude 5 и новее, Gemini 2.5 и новее, а также OpenAI-совместимые сервисы, которые возвращают размышления, например DeepSeek): пока ответ создается, размышления появляются в карточке над ним, затем карточка сворачивается в строку "Размышления: N с"; нажатие раскрывает или сворачивает ее. Параметры "Показывать размышления во время ответа" и "Сворачивать размышления после ответа" по умолчанию включены. Размышления сохраняются вместе с разговором, но не зачитываются вслух, не находятся поиском и не копируются, а скрипты их не получают.
- Нажмите "+" слева от поля ввода, чтобы добавить вложения, до 20 на сообщение: изображения выбираются в системном средстве выбора фото (слишком большие уменьшаются) и отправляются моделям, у которых включен "Ввод изображений"; текстовые файлы в UTF-8 (txt, md, json, csv, файлы кода и т. п.) отправляются как текст; PDF отправляются сервисам с поставщиком Anthropic или Gemini. Локальные модели пока не принимают вложения, а вложения, которые текущая модель не принимает, показаны бледнее и не отправляются. Вложения сохраняются вместе с сообщением, где показаны миниатюра или имя файла; нажатие открывает вложение в другом приложении. В следующих ходах прежние вложения отправляются снова в пределах контекста, а о тех, что не поместились, модель узнает только имя файла.
- При повторной генерации ответа или правке и повторной отправке сообщения последующая часть беседы не удаляется, а для этого шага создается новая версия: "< 2/3 >" под ответом переключает версии, последующие сообщения переключаются вместе с ней, а после повторного открытия разговора показывается последняя выбранная версия. Поиск, экспорт, озвучивание, статистика использования и продолжение разговора используют только показанную версию.
- Разговор можно экспортировать командой "Экспорт в Markdown" (место сохранения выбирается в системном диалоге сохранения, файл правильно отображается и в других программах для Markdown) или отправить командой "Поделиться изображением" (длинное изображение в оформлении страницы чата, отправляется через системную панель отправки) из меню чата или долгим нажатием на разговор на боковой панели. Экспортируются только показанные версии; если в разговоре есть размышления, сначала спрашивается, включать ли их, по умолчанию они не включаются.
- История разговоров хранится в формате v6, который также сохраняет глубину рассуждений и быстрый режим каждого разговора, размышления и их длительность для каждого ответа, а также сведения о вложениях и другие версии сообщений; разговоры, сохраненные версией 1.5.0 и более ранними, по-прежнему открываются. После возврата к версии 1.6.0 или более ранней видны только версии, показанные в тот момент: старая версия при открытии страницы чата удаляет другие версии всех разговоров, и после повторного обновления их нельзя восстановить.
- Микрофон в поле ввода: нажмите и говорите, распознанный текст вставляется в позицию курсора, чтобы вы проверили его перед отправкой; при установленном 3-Macaw Speech он диктует прямо в поле ввода в реальном времени: серый текст появляется по мере речи, каждое предложение становится окончательным, а прослушивание продолжается до повторного нажатия. Долгое нажатие начинает голосовой диалог, который сразу отправляет сказанное и снова слушает после озвучивания ответа; при установленном 3-Macaw Speech ни один круг не открывает экран распознавания, а круг, в котором микрофон занят или нет модели распознавания, использует окно.
- Озвучивание ответов: долго нажмите на ответ и выберите "Озвучить" или включите "Озвучивать ответы автоматически" в Настройки > Голос, чтобы слышать новые ответы во время генерации. Знаки заголовков и списков не читаются, а блок кода или таблица объявляются одной фразой.
- Отвечает на `VOICE_COMMAND` цифрового помощника 3-Macaw Speech: удерживайте кнопку питания, скажите вопрос и нажмите "3-Stone AI"; вопрос будет отправлен в новом диалоге, а ответ озвучен.

### Голос

******

Диктовка и озвучивание используют системные интерфейсы Android (`RecognizerIntent` и `TextToSpeech`), а при установленном 3-Macaw Speech также напрямую его сеансы диктовки. 3-Stone AI сам никогда не записывает звук и не запрашивает разрешение на микрофон. Если установлен 3-Macaw Speech, параметр "Предпочитать 3-Macaw Speech" в Настройки > Голос включен по умолчанию: нажатие на микрофон сразу диктует в поле ввода в реальном времени. Еще не окончательный текст показывается серым, каждое предложение становится окончательным после паузы примерно в секунду, и прослушивание продолжается, так что можно сказать несколько предложений подряд; диктовка заканчивается при повторном нажатии на микрофон (пока она идет, это кнопка остановки), через 15 секунд без речи или через 5 минут. Долгое нажатие на микрофон начинает голосовой диалог, который больше ни в одном круге не открывает экран распознавания: сказанное показывается серым в конце поля ввода, каждое предложение отправляется, как только вы его закончите, после озвучивания ответа прослушивание возобновляется, а 8 секунд без речи завершают диалог; нажмите микрофон во время прослушивания, чтобы сразу отправить сказанное. Выход из чата, отправка или переключение диалога завершают диктовку, а неотправленный текст остается в поле ввода. Если микрофон занят другим приложением (например, постоянным прослушиванием 3-Stove Agent) или модель распознавания еще не загружена, в этот раз вместо этого открывается окно распознавания 3-Macaw Speech; без разрешения на микрофон открывается его экран разрешений. Озвучивание использует его офлайн-голоса. Без него или при выключенном параметре используются приложение распознавания телефона и синтезатор речи по умолчанию, и каждая диктовка и каждый круг голосового диалога открывают экран распознавания. Во время озвучивания ответа нажмите строку состояния над полем ввода, чтобы прервать и сразу говорить, или используйте ее кнопку для выхода.

- **Несколько приложений распознавания речи каждый раз просят выбрать?** Оставьте "Предпочитать 3-Macaw Speech" включенным, чтобы сразу использовать 3-Macaw Speech. Если выключить, решает система, и в системном окне выбора можно назначить приложение по умолчанию.
- **Паузы между предложениями на медленном телефоне?** Некоторые голоса (например, MeloTTS и Kokoro) на медленных телефонах синтезируются медленнее, чем звучат. Выберите в 3-Macaw Speech голос по умолчанию AISHELL-3, Piper или Matcha.
- **Микрофон сообщает, что нет модели распознавания?** Окно 3-Macaw Speech поможет ее загрузить; до тех пор 3-Stone AI не переключается сам на другое приложение распознавания. Чтобы временно использовать другое приложение, выключите "Предпочитать 3-Macaw Speech".
- **3-Macaw Speech установлен, но почему иногда все равно открывается экран распознавания?** Если микрофон занят другим приложением (например, постоянным прослушиванием 3-Stove Agent), модель распознавания еще не загружена или к 3-Macaw Speech временно не удается подключиться, в этот раз используется его окно распознавания: окно приостанавливает прослушивание другого приложения и помогает загрузить модель, а в следующий раз снова сначала пробуется диктовка в реальном времени. Для диктовки в реальном времени на телефоне должен быть установлен AutoJs6; работает ли она и почему нет, показано в Настройки > Голос.
- **Продолжаются ли диктовка в реальном времени и голосовой диалог в фоне?** Нет. Они работают, только пока чат на экране, и завершаются при переходе в другое приложение, блокировке экрана или входящем звонке; уже показанный текст остается в поле ввода. Вернувшись в чат, нажмите или удерживайте микрофон, чтобы продолжить.
- **Как задать вопрос через цифрового помощника 3-Macaw Speech?** Назначьте 3-Macaw Speech цифровым помощником по умолчанию, удерживайте кнопку питания (или "Домой"), скажите вопрос и нажмите "3-Stone AI" на карточке результата. 3-Stone AI откроет новый диалог, сразу отправит вопрос и озвучит ответ; заблокированный телефон сначала разблокируйте. Если с предыдущего такого вопроса прошло меньше 10 секунд, текст только вставляется в поле ввода и не отправляется.
- **Куда уходит распознанный текст?** Выбранной модели, как и набранный текст; онлайн-модель передает его своему поставщику. 3-Macaw Speech работает полностью офлайн; другие приложения распознавания или синтеза речи могут использовать сеть.

Скрипты могут собрать такие же голосовые вопросы и ответы из модуля `speech` AutoJs6 (его предоставляет 3-Macaw Speech) и модуля `ai`, без интерфейса 3-Stone AI: `speech.listen` слушает одно предложение, `ai.chat` или `ai.stream` генерирует ответ, а `speech.speak` его озвучивает. Пример ниже прекращает слушать после первого предложения:

```js
let session = speech.listen({ timeoutMillis: 8000 });
session.on('final', () => session.stop());
session.on('end', () => {
    let question = session.result();
    console.log('Heard:', question);
    if (!question) return;
    ai.chat(question, { maxTokens: 256 })
        .then((response) => {
            console.log('Answer:', response.text);
            return speech.speak(response.text);
        })
        .catch((error) => console.error(error.code, error.message));
});
```

### Интерфейс плагина

******

Хост обнаруживает и вызывает плагин со следующими идентификаторами:

```text
service action: org.autojs.plugin.AI_PROVIDER
plugin id: three-stone-ai
protocol provider id: autojs6.three-stone-ai
engine: three-stone-ai
variant: default
protocol: V2 (2.0 / 2.1)
required host build: 5276
```

AI Provider V2 публикует единый постраничный каталог целей `local:*` и `profile:*`. Каждая цель отдельно объявляет provider, model, locality, настройку и доступность, capabilities, limits, controls и HTTPS origins. Каталог только с локальными целями объявляет ON_DEVICE/NONE; наличие online profile объявляет HYBRID/PLUGIN_MANAGED и точное объединение их HTTPS origins. Локальный backend profile является необязательным target control, а недоступные profile или цели не вызывают скрытого отката.

Требуются build хоста 5276 или новее и Android 7.0 или новее. Сборка создаёт APK armeabi-v7a, arm64-v8a, x86, x86_64, universal. Для x86 и armeabi-v7a используйте отдельный APK соответствующей архитектуры: доступны интерфейс, онлайн-ИИ и интеграция с хостом. Локальный вывод LiteRT-LM требует arm64-v8a или x86_64 и соответствующей нативной библиотеки в APK. APK universal содержит только 64-битные библиотеки и не устанавливается на устройства, поддерживающие только 32 бита.

### Состояние интеграции с хостом

******

> В AutoJs6 (сборка 5276 и новее) `ai.catalog()` возвращает все импортированные локальные модели и настроенные сетевые profile в едином каталоге целей с точным ID, поставщиком, моделью, типом размещения, состоянием настройки и доступности, возможностями, элементами управления, ограничениями, источником и локальными backend profile. Передайте точный `target` в `ai.ask`, `ai.chat`, `ai.stream` или `ai.session`; один `target` выбирает официальный плагин 3-Stone AI, а `plugin: true` использует объявленную им цель по умолчанию. Локальные цели могут предоставлять `cpu`, `gpu` и недоступный `npu`; сетевые цели не имеют локального profile выполнения. Недоступный backend или цель завершаются ошибкой без отката, а локальные и сетевые маршруты никогда не переключаются автоматически. Завершенные и потоковые ответы содержат target, plugin, profile, рассуждение, причину завершения, полный usage и измеренную поставщиком длительность. Стабильные ошибки различают отсутствующего или отключенного поставщика, неизвестную, ненастроенную, недоступную или несовместимую по возможностям цель и недоступный backend. `responseSchema` включает структурированный вывод; `structuredJson: true` без schema использует корень object по умолчанию, а постоянные сессии фиксируют один target, schema и необязательный backend для всех ходов.

Приложения с независимой подписью запрашивают доступ к ИИ в плагине с привязкой к идентичности и установке; отзыв в настройках останавливает активные запросы. Разрешение охватывает локальные модели и сохраненные сетевые учетные записи. Сетевые вызовы могут расходовать платную квоту. В Node.js, Bun и Workers используйте ai.hasAccess() и ai.requestAccess().

### Безопасность и конфиденциальность

******

Плагин запрашивает `INTERNET` для загрузок рекомендуемых моделей по запросу пользователя, запросов к настроенным онлайн-целям и обновлений публичного каталога моделей с GitHub на странице "Модели и сервисы". Обновления каталога не требуют ключа API, не запускают генерацию и не начинаются при активации плагина или локальной генерации. Плагин не запрашивает широкого доступа к хранилищу. Загрузки файлов моделей используют неизменяемые HTTPS-версии, закреплённые размер и SHA-256 и пишут только во временный файл в закрытом каталоге приложения `files/model-downloads` (после прерывания загрузка автоматически повторяется и продолжается); модель перемещается в `files/models` и передается импорту для атомарной активации только после успешной проверки заголовка LiteRT-LM, размера, хеша, flush и fsync. Импорт по-прежнему читает только URI выбора, пишет проверенную копию в `files/models` и активирует её атомарно. Исходная служба Provider для AutoJs6 также проверяет пакет AutoJs6, UID, подписи, target metadata и границы объявленных origin. Голосовые функции не запрашивают разрешение на микрофон: записывает приложение распознавания или 3-Macaw Speech. Диктовка в реальном времени и голосовой диалог без экрана распознавания напрямую подключаются к речевому сервису 3-Macaw Speech (`org.autojs.plugin.SPEECH`, подключиться к нему могут только приложения с разрешением плагинов AutoJs6); 3-Stone AI получает только распознанный текст и никогда не получает звук. Распознанный и озвучиваемый текст не записывается в журнал, а продиктованные сообщения хранятся так же, как набранные. Размышления, возвращенные моделью, хранятся только в локальной истории разговоров; в следующих ходах они не отправляются обратно онлайн-сервису, и скрипты не получают их через интерфейс плагина. Вложения чата читаются через системные средства выбора, без разрешений на доступ к хранилищу или фото; выбранные файлы копируются в закрытую папку приложения `files/attachments`, отправляются только сервису выбранной онлайн-модели и удаляются вместе с разговором. При открытии вложения в другом приложении временный доступ на чтение выдается через FileProvider, который открывает только `files/attachments`. Длинное изображение для отправки записывается в кэш приложения `cache/share` и передается панели отправки отдельным FileProvider, который открывает только этот каталог; перед каждым новым изображением удаляются изображения старше 24 часов и хранится не более 3. Экспортированный Markdown записывается только туда, куда вы укажете в системном диалоге сохранения. Среди собственных заголовков запросов сервиса секретные значения, как и ключ API, хранятся на устройстве в зашифрованном виде через Android Keystore; интерфейс их не показывает, в экспорт они не попадают, а после импорта, клонирования или смены поставщика либо источника HTTPS их нужно ввести заново. Ключи API и секретные значения, встретившиеся в подробностях ошибок от поставщика, заменяются на `[redacted]`. Постоянные значения хранятся открытым текстом и попадают в экспорт, поэтому не вводите ключи как постоянные значения.

### Рабочие ограничения

******

- Импорт модели имеет жесткий предел 8 GiB и должен оставить не менее 256 MiB свободного места.
- Хранится только одна незавершенная загрузка модели; начало загрузки другой модели отменяет ее (окно подтверждения об этом предупреждает). Общая библиотека загрузки официальных плагинов AutoJs6 пишет загрузку в закрытый каталог приложения `files/model-downloads/<sha256>/model.litertlm.part`: при обрыве сети она автоматически повторяет попытку дважды (примерно через 2 и 5 секунд), каждый раз продолжая запросом HTTP Range; пауза, закрытие приложения или завершение процесса сохраняют этот файл, а при продолжении или повторе сначала заново проверяется уже полученная часть, затем загрузка продолжается; отмена, недопустимое содержимое или несовпадение хеша удаляют файл. Незавершенная загрузка никогда не удаляется из-за давности. Проверенный файл перемещается в `files/models/.download-<sha256>.part` и передается импорту. При холодном запуске самая новая загрузка рекомендуемой модели, которая еще не импортирована, восстанавливается как приостановленная, остальные удаляются; незавершенный файл, оставленный версией 1.7.0 в `files/models/.download-<sha256>.part`, переносится на новое место и продолжается с уже полученных байтов.
- Загруженные и импортированные локальные модели хранятся в закрытых данных приложения (`files/models`), а занимаемый ими объём показан на карточках раздела "Локальные модели" и на панели выбора модели. Удаление плагина или очистка его данных удаляет и эти модели; файлы моделей, ранее загруженные в другое место, можно добавить через "Импорт файла модели".
- Координатор одного импорта на уровне приложения сохраняет выполняемую работу при пересоздании Activity. Синхронизированный через fsync pending journal обеспечивает восстановление при холодном запуске и очистку stale временных файлов `.incoming`, `.current` и `.pending`. Восстановление удаляет только destination, созданный текущей попыткой и никогда не опубликованный через current metadata; опубликованные, current и исторические поколения с hash сохраняются.
- Чтобы избежать межпроцессных гонок с изолированным процессом `:provider`, импорт не удаляет автоматически предыдущие поколения моделей с именами по hash SHA-256. В разделе "Локальные модели" можно удалить модели из каталога и очистить файлы с hash-именами, на которые каталог больше не ссылается.
- В процессе активен не более одного сеанса генерации. Дескрипторы дублируются до асинхронной работы и закрываются по квотам протокола.
- Provider кэширует не более одного Engine по паре SHA-256 модели и backend profile. Запросы с той же парой используют его повторно; изменение любого ключа, пять минут простоя или явное давление памяти безопасно освобождают Engine.
- Проверка модели подтверждает только успешный вызов `Engine.initialize()` на текущем устройстве со встроенной средой выполнения; она не оценивает качество вывода и может быть повторена после смены устройства или среды.
- Provider объявляет предел контекста 256 KiB и предел вывода 64 KiB. Запросы и модели могут задавать меньшие пределы.
- Schema ответа должна быть объектом JSON размером не более 64 KiB. Поддерживаются ключевые слова, реализованные во встроенной среде LiteRT-LM/LLGuidance; завершенный вывод строго разбирается и проверяется, поэтому для всего значения JSON требуется достаточный `maxTokens`.
- `maxTokens` принимает целые числа от 1 до 2 147 483 647. Если его опустить, число выходных токенов определяется моделью или движком; защитный предел вывода провайдера 64 KiB сохраняется. `temperature` должен быть конечным и неотрицательным, `topK` - положительным целым, а `topP` - конечным числом от 0 до 1. Если все три параметра sampling опущены, сохраняются настройки модели или engine; при частичном переопределении пропуски заполняются базовыми значениями LiteRT-LM: `topK: 1`, `topP: 0.95`, `temperature: 1`.
- Поток использует конечные credits и ограниченные chunks, исключая неограниченный буфер и callbacks без обратного давления.
- Количество токенов usage берется непосредственно из счетчиков KV cache и decode объекта Conversation LiteRT-LM без оценки по числу символов. `durationMillis` измеряет только вызов генерации плагина и не включает обнаружение, привязку, перечисление моделей и диспетчеризацию хоста.
- Постоянный `ai.session` допускает один активный ход и сохраняет нативный Conversation после нормального завершения; после отмены, timeout, ошибки генерации или явного закрытия его нужно создать заново.
- Отмена, закрытие сеанса и timeout прекращают публикацию и завершают запрос одним конечным состоянием.
- В Настройки > Модели и сервисы откройте "Сведения о сервисе" и включите "Ввод изображений" в меню строки каждой модели из списка, которая принимает изображения. В существующих сервисах он по умолчанию отключен. Изображения отправляются только этому сервису. LiteRT и постоянный ai.session остаются текстовыми; снимки Agent требуют Android 11+, совместимых версий AutoJs6 и AI Agent, группы observe и включенного ввода изображений для точно выбранной модели.
- Ограничения вложений: изображение до 5 МБ, текстовый файл до 256 КБ в корректной кодировке UTF-8, PDF до 32 МБ и не более 100 страниц (зашифрованные PDF не принимаются), до 20 вложений на сообщение и до 48 МБ на разговор. Исходный объем вложений в одном запросе: 32 МБ для Anthropic и OpenAI-совместимых сервисов, 20 МБ для Gemini; OpenAI-совместимые сервисы не принимают PDF. Сообщение сверх лимита выбранной цели не отправляется, и лимит указывается.
- На каждом шаге хранится не более 8 версий; когда скрытые версии в разговоре превышают в сумме примерно 2 MiB, первыми удаляются самые старые. При удалении сообщения с несколькими версиями удаляется только показанная версия.
- Длинное изображение выше 16384 пикселей пропорционально уменьшается; при нехватке памяти масштаб уменьшается вдвое и попытка повторяется, а если и это не помогает, предлагается экспортировать в Markdown. Разговор, ответ в котором еще генерируется, экспортировать нельзя.
- AiGoCode gpt-5.6-sol прошел реальные проверки с исходным изображением и изображением в результате инструмента на Provider 1.2.0 / build 218. Эти проверки с синтетическими изображениями не подтверждают поддержку других целей или выполнение полной визуальной задачи Agent.
- Ошибки онлайн-генерации передают только фиксированные категории `ONLINE_*` в необязательном поле `providerCode`. Неизвестные исключения не имеют категории; URL, учётные данные, ответы сервиса и исходный текст исключений исключены. Код ошибки и политика повторов не меняются.
- У каждого сервиса не более 16 собственных заголовков запросов: имена длиной 1 - 64 байта состоят только из символов token по RFC 9110 и уникальны без учета регистра; постоянные и секретные значения длиной 1 - 1024 байта состоят только из видимых символов ASCII и пробелов; все заголовки запросов вместе занимают не более 8192 байт (каждая запись "Создается для каждого диалога" считается за 36 байт). 22 заголовка, которые отправляет плагин или которыми управляет HTTP-соединение, изменить нельзя, при импорте они тоже отклоняются. Секретный заголовок, значение которого ни разу не задавалось, не отправляется; если запись секретного значения не удается прочитать, весь запрос завершается ошибкой, а не отправляется без заголовка.

### Необъявленные возможности

******

- Интерфейс плагина не объявляет вывод reasoning, поэтому скрипты не получают размышления (они показываются только в чате лаунчера). Локальные цели LiteRT-LM по-прежнему не объявляют tools.
- Разрешено до 16 раундов и 32 ожидающих вызовов. Результаты должны точно соответствовать ожидающему пакету; ограничения контекста/вывода, отмена и исходный срок сохраняются. Нативные инструменты не совмещаются с постоянными сессиями ai.session; начальная история не принимает роль tool.
- Загрузка файлов моделей с произвольных URL не поддерживается. Список моделей можно обновлять из публичного каталога проекта, но это не создает сервисы и не проверяет права доступа аккаунта. Чат launcher и AI Provider V2 показывают только импортированные локальные модели и явно настроенные онлайн-сервисы; локальные модели для загрузки ограничены закрепленными встроенными рекомендациями.
- Вывод NPU не объявлен: profile виден как `unavailable` с причиной `npu-runtime-not-packaged`. GPU объявляется только при загрузке `libOpenCL.so`, а расширение `.litertlm` по-прежнему не гарантирует инициализацию модели.

# v1.9.0

###### 2026/11/28

* `Функция` При установленном 3-Macaw Speech нажатие на микрофон диктует прямо в поле ввода в реальном времени вместо открытия экрана распознавания: еще не окончательный текст показывается серым, каждое предложение становится окончательным после паузы, и прослушивание продолжается, так что можно сказать несколько предложений подряд; диктовка заканчивается при повторном нажатии на микрофон (пока она идет, это кнопка остановки), через 15 секунд без речи или через 5 минут. Выход из чата, отправка или переключение диалога завершают диктовку, а уже показанный текст остается в поле ввода
* `Функция` При установленном 3-Macaw Speech голосовой диалог, который начинается долгим нажатием на микрофон, тоже больше не открывает экран распознавания: сказанное показывается серым в конце поля ввода, каждое предложение отправляется, как только вы его закончите, а после озвучивания ответа прослушивание возобновляется; диалог завершается через 8 секунд без речи, кнопкой выхода в строке состояния или при выходе из чата, а нажатие на микрофон во время прослушивания сразу отправляет сказанное
* `Исправление` При продолжительном диалоге с локальной моделью (особенно в голосовом диалоге) следующий ход иногда прерывался ошибкой "Resource cache already has an active lease": он запрашивал модель раньше, чем предыдущий ход её возвращал. Теперь следующий ход ждёт возврата (обычно меньше секунды); если модель действительно занята другой задачей дольше минуты, вместо внутренней ошибки показывается "Модель на устройстве всё ещё занята другой задачей"
* `Исправление` В длинных диалогах с локальной моделью более ранние сообщения так и не сжимались в сводку (каждая попытка заканчивалась неудачей), поэтому модель чаще забывала начало диалога; теперь локальная модель составляет сводку после 30 секунд паузы в диалоге и уступает новому ходу, начавшемуся в это время
* `Исправление` Если после чата с локальной моделью скрипт AutoJs6 вызывал локальную модель (или наоборот), чат и служба скриптов загружали каждый свою копию модели и расход памяти удваивался (для Gemma 4 E2B примерно на 1,5 ГБ больше); на телефонах с нехваткой памяти система могла завершить вызов скрипта ("BINDER_DIED"). Теперь перед загрузкой модели одна сторона просит другую вернуть неиспользуемую копию, и по копии у обеих бывает только тогда, когда обе одновременно генерируют ответ
* `Исправление` Если оформление плагина отличалось от системного (например, светлая система и плагин, который следует тёмному AutoJs6), при холодном запуске сначала показывались тема и язык системы, а затем всё переключалось на оформление плагина. Теперь плагин запоминает последние язык, тему и цвет оформления AutoJs6, и первый экран холодного запуска сразу использует их; на Android 12 и новее плагин также сообщает системе своё оформление, поэтому начиная со второго запуска после установки и заставка сразу использует его (на Android 11 и более ранних версиях заставка по-прежнему следует системе)
* `Исправление` Голосовой диалог и диктовка в реальном времени в поле ввода показывали "слушаю" ещё до того, как микрофон действительно начинал запись, поэтому первые слова могли теряться; теперь сначала показывается "подготовка микрофона", а "слушаю" появляется, когда запись началась
* `Улучшение` Если микрофон занят другим приложением (например, постоянным прослушиванием 3-Stove Agent) или у 3-Macaw Speech еще нет модели распознавания, эта диктовка или этот круг диалога вместо этого открывает его окно распознавания (окно приостанавливает прослушивание другого приложения и помогает загрузить модель); без разрешения на микрофон открывается экран разрешений 3-Macaw Speech. В Настройки > Голос показано, работает ли диктовка в поле ввода в реальном времени, а если нет, то почему. Без 3-Macaw Speech или при выключенном "Предпочитать 3-Macaw Speech" все работает как раньше

# v1.8.0

###### 2026/11/27

* `Подсказка` После добавления заголовков запросов к сервису конфигурация сервисов сохраняется в новом формате (как и экспортированные файлы с заголовками запросов), который версия 1.7.2 и более ранние прочитать не могут. Чтобы вернуться к старой версии, сначала удалите заголовки запросов у всех сервисов и сохраните
* `Функция` К онлайн-сервисам можно добавлять собственные заголовки запросов: на странице "Модели и сервисы" откройте сервис и нажмите "Заголовки запросов" в разделе "Подключение", чтобы добавить, изменить или удалить их, до 16 на сервис. Есть три источника значения: постоянное значение; секретное значение (отметьте "Секретное"; отмечено по умолчанию, если имя содержит auth, key, token или secret); "Создается для каждого диалога" (не меняется в пределах диалога, даже после переключения на другую модель того же сервиса). Их можно использовать с сервисами всех 6 поставщиков. Заголовки запросов применяются автоматически вместе с конфигурацией сервиса, поэтому скрипты менять не нужно, а постоянные сессии скриптов (ai.session) тоже используют фиксированный идентификатор сессии
* `Функция` Секретные значения хранятся на этом устройстве в зашифрованном виде; в интерфейсе показывается только "Задано", при редактировании они не отображаются и не попадают в экспорт. После импорта или клонирования сервиса секретные значения становятся "Не задано", а на карточке сервиса появляется метка "Нужно значение заголовка"; пока значение не введено заново, этот заголовок не отправляется. При смене поставщика или источника HTTPS и сохранении сохраненные секретные значения удаляются вместе с ключом API. Если в подробностях ошибки от поставщика встречается ключ API или секретное значение, оно заменяется на [redacted]
* `Функция` Заголовки, которые отправляет сам плагин (например, Authorization, x-api-key, Content-Type), и заголовки, которыми управляет HTTP-соединение (например, Host, Content-Length), изменить нельзя, и диалог объясняет причину; User-Agent изменить можно (он заменяет значение плагина по умолчанию), а anthropic-beta объединяется со значением, которое плагин вычисляет для запроса. Если формат или длина имени либо значения не подходят или все заголовки запросов вместе превышают 8192 байта, диалог тоже объясняет причину
* `Функция` При добавлении заголовка запроса можно развернуть "Частые шаблоны": выбор "Сессия OpenCode Go" или "Указание источника для OpenRouter" добавляет соответствующие заголовки, а выбор Helicone или Cloudflare AI Gateway заполняет имя, так что остается ввести только ключ. Если адрес сервиса находится на opencode.ai, но заголовка сессии x-opencode-session нет, страница сведений о сервисе показывает подсказку и кнопку "Добавить"; если при проверке подключения или в чате приходит ошибка MissingSessionID, сообщение об ошибке объясняет причину и предлагает кнопку "Добавить заголовок сессии"
* `Исправление` Если язык плагина и язык системы пишутся в противоположных направлениях (например, плагин переключен на арабский в системе на китайском), кнопки внизу диалогов, такие как "Отмена" и "ОК", теперь отражаются вместе с остальным интерфейсом, а не остаются на стороне языка системы

### Сборка

******

```powershell
.\gradlew.bat :app:assembleDebug
```

Релизная сборка:

```powershell
.\gradlew.bat :app:assembleRelease
```

Параметры берутся из `version.properties`. Текущий минимальный SDK 24, целевой SDK 37, требуется JDK 21 или новее.

ABI протокола предоставляется локальными AAR репозитория в `libs`:

```text
common-plugin-api.aar
protocol-wire-api.aar
ai-common-api.aar
ai-provider-api.aar
```

Runtime использует LiteRT-LM 0.15.0 из Maven. Релиз сохраняет классы LiteRT-LM и создает два APK для ABI и один universal APK.
