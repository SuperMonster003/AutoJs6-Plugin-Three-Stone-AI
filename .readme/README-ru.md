### Введение

******

3-Stone AI - официальный плагин AutoJs6 для генерации текста ИИ. Он выполняет импортированные пользователем модели LiteRT-LM на явно выбранном CPU или совместимом GPU backend и использует настроенные пользователем онлайн-сервисы для онлайн-генерации. Локальные и сетевые назначения используют единый каталог целей AI Provider V2, управляемый потоковый конвейер и явную границу выбора. Локальные цели не обращаются к сети и не отправляют данные; онлайн-цель выполняется только после явного выбора и остается привязанной к управляемым плагином учетным данным и объявленному HTTPS origin.

******

### Функции

******

- Импорт пакета модели `.litertlm` через системный выбор Android и хранение проверенной копии в закрытом хранилище приложения.
- Загрузка в один шаг закреплённой общедоступной рекомендуемой модели LiteRT Community из встроенного каталога: файл записывается в закрытое хранилище приложения и импортируется автоматически после точной проверки размера и SHA-256. Загружаемая модель показывается карточкой в разделе "Локальные модели" с прогрессом, паузой, отменой и повтором при ошибке, а прерванная загрузка продолжается с уже полученной части; окно подтверждения показывает минимальный объём памяти для модели и предупреждает, если у устройства меньше.
- Проверка закрытого хранилища до открытия системного выбора, отображение текущего бюджета импорта и ожидаемого размера закрытой копии, а также повторная проверка выбранного файла до копирования.
- Создание локальных запросов из истории system, user и assistant в обычном тексте.
- Передача `temperature`, `topK`, `topP` и `maxTokens` из `ai.ask`, `ai.chat` и `ai.stream` AutoJs6 в LiteRT-LM.
- Нативное ограничение вывода по JSON Schema в LiteRT-LM через `structuredJson` и `responseSchema` AutoJs6; завершенное значение остается текстом JSON для `JSON.parse`.
- Возврат точных количеств входных, выходных и общих токенов LiteRT-LM вместе с длительностью генерации провайдера через `ai.chat().usage` и потоковые события usage.
- Сохранение многоходового контекста в одном нативном Conversation LiteRT-LM через `ai.session` AutoJs6 с передачей только нового пользовательского запроса в следующих ходах.
- Повторное использование инициализированного Engine по SHA-256 модели без повторного холодного запуска для последовательных запросов к той же модели.
- При необходимости однократно инициализировать каждую импортированную модель, сохранять статус Доступна/Несовместима и повторно запускать проверку из менеджера моделей.
- Последовательная передача текстовых chunks с обратным давлением credits и публикация ровно одного конечного состояния завершения, ошибки или отмены.
- Просмотр, переименование, проверка и удаление импортированных моделей в разделе "Локальные модели", на каждой карточке указан занимаемый моделью объём, а файлы моделей без ссылок очищаются одним нажатием.
- Явный выбор `cpu`, `gpu` или `npu` через AutoJs6: CPU используется по умолчанию, GPU доступен только после проверки загрузки OpenCL, а NPU помечается недоступным, поскольку EAP runtime не включен.
- Управление встроенными и настраиваемыми онлайн-сервисами, учетными данными Android Keystore, единственной целью по умолчанию (онлайн- или локальной моделью), тарифицируемыми сетями и явными ограниченными проверками подключения в разделе Настройки > Модели и сервисы. Сервисы редактируются на полноэкранной странице "Сведения о сервисе": в сервис можно добавить несколько моделей, менять их порядок перетаскиванием и выбрать предпочтительную, а изменения сохраняются только по галочке.
- Закрепление каждого диалога launcher за снимком локальной или онлайн-цели; при смене цели заполненного диалога рекомендуется новый, а продолжение требует явного подтверждения и сохраняет запись об изменении.
- Сохранять для каждого ответа ассистента снимок фактических target/provider/model/locality; повторная генерация точно использует записанную исходную цель, явно завершается ошибкой при изменении её идентичности или недоступности и не переключается молча на текущую цель диалога.
- Сохранять ошибки локальной и облачной генерации в выбранной границе: чат лаунчера добавляет ограниченную причину без чувствительных данных, явно сообщает об отсутствии автоматического переключения между границами и предлагает ручной выбор другой цели без удаления частичного вывода.
- Нативные вызовы инструментов для онлайн-целей OpenAI-compatible, Anthropic Messages и Gemini GenerateContent, включая потоковые аргументы, параллельные вызовы и продолжение после результатов.
- Ввод JPEG/PNG и изображения в результатах инструментов через согласованный AI Provider 2.1 с настройкой для каждой модели.
- Обновлять предустановленные онлайн-модели из публичного каталога проекта на GitHub. Автообновление включено по умолчанию и проверяет каталог раз в 24 часа при открытии страницы "Модели и сервисы"; в меню раздела "Онлайн-сервисы" его можно отключить или обновить вручную. Соблюдается настройка сетей с тарификацией, без сети или при ошибке сохраняется кэшированный или встроенный список, а сохраненные сервисы и пользовательские ID не меняются.
- Сгруппировать модели по поставщикам и расширить выбор OpenRouter моделями Qwen, Kimi, GLM, Grok, Meta и MiniMax, сохраняя точные ID.
- Унифицированы плоские группы настроек, строки и скругленные диалоги по центру. Язык, ночной режим, цвет и значок меняются только после подтверждения; отмена сохраняет прежние значения. Цвет по умолчанию следует AutoJs6, доступны общая палитра, HEX/RGB и локальный предпросмотр. Нейтральный фон остается постоянным, элементы следуют теме. По умолчанию выбран автоматический адаптивный значок, обновление сохраняет явный выбор.
- Генерация ответов больше не привязана к экрану чата: она продолжается при повороте экрана, смене темной темы, языка или размера текста сообщений, а ответ, завершившийся, пока вы были вне чата, показывается полностью при возвращении (если система завершит процесс приложения, ответ все же прервется). Нажатие "Остановить", создание или переключение разговора, смена модели и удаление сообщений обрывают онлайн-запрос в течение 1 секунды, и остановленный ответ больше не увеличивает расход.
- В онлайн-сервисах можно задать глубину рассуждений по умолчанию (По умолчанию, низкая, средняя, высокая, очень высокая, максимальная; при "По умолчанию" решает модель), а сервисы Anthropic могут по умолчанию включать быстрый режим (ответы быстрее, но дороже); оба параметра можно изменить только для текущего разговора, изменение сохраняется вместе с ним. Если модель не поддерживает выбранный уровень, используется ближайший более низкий. Скрипты, вызывающие ИИ через интерфейс плагина, эти два параметра не используют.
- Выбор модели открывается панелью снизу: избранные модели находятся в группе "Избранное" вверху, остальные сгруппированы по сервисам, и каждая модель показана один раз; результаты поиска не делятся на группы; под каждой строкой указан сервис (у локальных моделей размер файла) и метки ввода изображений, рассуждений и быстрого режима; на панели можно сразу изменить глубину рассуждений и быстрый режим текущего разговора, а пункт "Управление моделями и сервисами" внизу открывает настройки моделей. Полоса вверху чата показывает глубину рассуждений и быстрый режим текущего разговора.
- Показывает, как модель размышляет (Claude 5 и новее, Gemini 2.5 и новее, а также OpenAI-совместимые сервисы, которые возвращают размышления, например DeepSeek): пока ответ создается, размышления появляются в карточке над ним, затем карточка сворачивается в строку "Размышления: N с"; нажатие раскрывает или сворачивает ее. Параметры "Показывать размышления во время ответа" и "Сворачивать размышления после ответа" по умолчанию включены. Размышления сохраняются вместе с разговором, но не зачитываются вслух, не находятся поиском и не копируются, а скрипты их не получают.
- История разговоров хранится в формате v6, который также сохраняет глубину рассуждений и быстрый режим каждого разговора, а также размышления и их длительность для каждого ответа; разговоры, сохраненные версией 1.5.0 и более ранними, по-прежнему открываются.
- Микрофон в поле ввода: нажмите и говорите, распознанный текст вставляется в позицию курсора, чтобы вы проверили его перед отправкой; долгое нажатие начинает голосовой диалог, который сразу отправляет сказанное и снова слушает после озвучивания ответа.
- Озвучивание ответов: долго нажмите на ответ и выберите "Озвучить" или включите "Озвучивать ответы автоматически" в Настройки > Голос, чтобы слышать новые ответы во время генерации. Знаки заголовков и списков не читаются, а блок кода или таблица объявляются одной фразой.
- Отвечает на `VOICE_COMMAND` цифрового помощника 3-Macaw Speech: удерживайте кнопку питания, скажите вопрос и нажмите "3-Stone AI"; вопрос будет отправлен в новом диалоге, а ответ озвучен.

### Голос

******

Диктовка и озвучивание используют системные интерфейсы Android (`RecognizerIntent` и `TextToSpeech`). 3-Stone AI сам никогда не записывает звук и не запрашивает разрешение на микрофон. Если установлен 3-Macaw Speech, параметр "Предпочитать 3-Macaw Speech" в Настройки > Голос включен по умолчанию: диктовка открывает его офлайн-окно распознавания, а озвучивание использует его офлайн-голоса. Без него или при выключенном параметре используются приложение распознавания телефона и синтезатор речи по умолчанию. В версии 1.4.0 каждый круг голосового диалога открывает экран распознавания; во время озвучивания ответа нажмите строку состояния над полем ввода, чтобы прервать и сразу говорить, или используйте ее кнопку для выхода.

- **Несколько приложений распознавания речи каждый раз просят выбрать?** Оставьте "Предпочитать 3-Macaw Speech" включенным, чтобы сразу использовать 3-Macaw Speech. Если выключить, решает система, и в системном окне выбора можно назначить приложение по умолчанию.
- **Паузы между предложениями на медленном телефоне?** Некоторые голоса (например, MeloTTS и Kokoro) на медленных телефонах синтезируются медленнее, чем звучат. Выберите в 3-Macaw Speech голос по умолчанию AISHELL-3, Piper или Matcha.
- **Микрофон сообщает, что нет модели распознавания?** Окно 3-Macaw Speech поможет ее загрузить; до тех пор 3-Stone AI не переключается сам на другое приложение распознавания. Чтобы временно использовать другое приложение, выключите "Предпочитать 3-Macaw Speech".
- **Как задать вопрос через цифрового помощника 3-Macaw Speech?** Назначьте 3-Macaw Speech цифровым помощником по умолчанию, удерживайте кнопку питания (или "Домой"), скажите вопрос и нажмите "3-Stone AI" на карточке результата. 3-Stone AI откроет новый диалог, сразу отправит вопрос и озвучит ответ; заблокированный телефон сначала разблокируйте. Если с предыдущего такого вопроса прошло меньше 10 секунд, текст только вставляется в поле ввода и не отправляется.
- **Куда уходит распознанный текст?** Выбранной модели, как и набранный текст; онлайн-модель передает его своему поставщику. 3-Macaw Speech работает полностью офлайн; другие приложения распознавания или синтеза речи могут использовать сеть.

### Интерфейс плагина

******

Хост обнаруживает и вызывает плагин со следующими идентификаторами:

```text
service action: org.autojs.plugin.AI_PROVIDER
plugin id: three-stone-ai
protocol provider id: autojs6.three-stone-ai
engine: three-stone-ai
variant: default
protocol: V2 (2.0 / 2.1)
required host build: 5276
```

AI Provider V2 публикует единый постраничный каталог целей `local:*` и `profile:*`. Каждая цель отдельно объявляет provider, model, locality, настройку и доступность, capabilities, limits, controls и HTTPS origins. Каталог только с локальными целями объявляет ON_DEVICE/NONE; наличие online profile объявляет HYBRID/PLUGIN_MANAGED и точное объединение их HTTPS origins. Локальный backend profile является необязательным target control, а недоступные profile или цели не вызывают скрытого отката.

Требуются build хоста 5276 или новее и Android 7.0 или новее. Сборка создаёт APK armeabi-v7a, arm64-v8a, x86, x86_64, universal. Для x86 и armeabi-v7a используйте отдельный APK соответствующей архитектуры: доступны интерфейс, онлайн-ИИ и интеграция с хостом. Локальный вывод LiteRT-LM требует arm64-v8a или x86_64 и соответствующей нативной библиотеки в APK. APK universal содержит только 64-битные библиотеки и не устанавливается на устройства, поддерживающие только 32 бита.

### Состояние интеграции с хостом

******

> В AutoJs6 (сборка 5276 и новее) `ai.catalog()` возвращает все импортированные локальные модели и настроенные сетевые profile в едином каталоге целей с точным ID, поставщиком, моделью, типом размещения, состоянием настройки и доступности, возможностями, элементами управления, ограничениями, источником и локальными backend profile. Передайте точный `target` в `ai.ask`, `ai.chat`, `ai.stream` или `ai.session`; один `target` выбирает официальный плагин 3-Stone AI, а `plugin: true` использует объявленную им цель по умолчанию. Локальные цели могут предоставлять `cpu`, `gpu` и недоступный `npu`; сетевые цели не имеют локального profile выполнения. Недоступный backend или цель завершаются ошибкой без отката, а локальные и сетевые маршруты никогда не переключаются автоматически. Завершенные и потоковые ответы содержат target, plugin, profile, рассуждение, причину завершения, полный usage и измеренную поставщиком длительность. Стабильные ошибки различают отсутствующего или отключенного поставщика, неизвестную, ненастроенную, недоступную или несовместимую по возможностям цель и недоступный backend. `responseSchema` включает структурированный вывод; `structuredJson: true` без schema использует корень object по умолчанию, а постоянные сессии фиксируют один target, schema и необязательный backend для всех ходов.

Приложения с независимой подписью запрашивают доступ к ИИ в плагине с привязкой к идентичности и установке; отзыв в настройках останавливает активные запросы. Разрешение охватывает локальные модели и сохраненные сетевые учетные записи. Сетевые вызовы могут расходовать платную квоту. В Node.js, Bun и Workers используйте ai.hasAccess() и ai.requestAccess().

### Безопасность и конфиденциальность

******

Плагин запрашивает `INTERNET` для загрузок рекомендуемых моделей по запросу пользователя, запросов к настроенным онлайн-целям и обновлений публичного каталога моделей с GitHub на странице "Модели и сервисы". Обновления каталога не требуют ключа API, не запускают генерацию и не начинаются при активации плагина или локальной генерации. Плагин не запрашивает широкого доступа к хранилищу. Загрузки файлов моделей используют неизменяемые HTTPS-версии, закреплённые размер и SHA-256 и пишут только во временный файл в закрытом каталоге приложения `files/models` (после прерывания загрузка продолжается); модель передается импорту для атомарной активации только после успешной проверки заголовка LiteRT-LM, размера, хеша, flush и fsync. Импорт по-прежнему читает только URI выбора, пишет проверенную копию в `files/models` и активирует её атомарно. Исходная служба Provider для AutoJs6 также проверяет пакет AutoJs6, UID, подписи, target metadata и границы объявленных origin. Голосовые функции не запрашивают разрешение на микрофон: записывает приложение распознавания. Распознанный и озвучиваемый текст не записывается в журнал, а продиктованные сообщения хранятся так же, как набранные. Размышления, возвращенные моделью, хранятся только в локальной истории разговоров; в следующих ходах они не отправляются обратно онлайн-сервису, и скрипты не получают их через интерфейс плагина.

### Рабочие ограничения

******

- Импорт модели имеет жесткий предел 8 GiB и должен оставить не менее 256 MiB свободного места.
- Хранится только одна незавершенная загрузка модели; начало загрузки другой модели отменяет ее (окно подтверждения об этом предупреждает). Загрузка пишется в `files/models/.download-<sha256>.part`: пауза, обрыв сети, закрытие приложения или завершение процесса сохраняют этот файл, а при продолжении или повторе сначала заново проверяется уже полученная часть, затем загрузка продолжается; отмена, недопустимое содержимое или несовпадение хеша удаляют файл. При холодном запуске самый новый частичный файл рекомендуемой модели, которая еще не импортирована, восстанавливается как приостановленный, остальные удаляются.
- Загруженные и импортированные локальные модели хранятся в закрытых данных приложения (`files/models`), а занимаемый ими объём показан на карточках раздела "Локальные модели" и на панели выбора модели. Удаление плагина или очистка его данных удаляет и эти модели; файлы моделей, ранее загруженные в другое место, можно добавить через "Импорт файла модели".
- Координатор одного импорта на уровне приложения сохраняет выполняемую работу при пересоздании Activity. Синхронизированный через fsync pending journal обеспечивает восстановление при холодном запуске и очистку stale временных файлов `.incoming`, `.current` и `.pending`. Восстановление удаляет только destination, созданный текущей попыткой и никогда не опубликованный через current metadata; опубликованные, current и исторические поколения с hash сохраняются.
- Чтобы избежать межпроцессных гонок с изолированным процессом `:provider`, импорт не удаляет автоматически предыдущие поколения моделей с именами по hash SHA-256. В разделе "Локальные модели" можно удалить модели из каталога и очистить файлы с hash-именами, на которые каталог больше не ссылается.
- В процессе активен не более одного сеанса генерации. Дескрипторы дублируются до асинхронной работы и закрываются по квотам протокола.
- Provider кэширует не более одного Engine по паре SHA-256 модели и backend profile. Запросы с той же парой используют его повторно; изменение любого ключа, пять минут простоя или явное давление памяти безопасно освобождают Engine.
- Проверка модели подтверждает только успешный вызов `Engine.initialize()` на текущем устройстве со встроенной средой выполнения; она не оценивает качество вывода и может быть повторена после смены устройства или среды.
- Provider объявляет предел контекста 256 KiB и предел вывода 64 KiB. Запросы и модели могут задавать меньшие пределы.
- Schema ответа должна быть объектом JSON размером не более 64 KiB. Поддерживаются ключевые слова, реализованные во встроенной среде LiteRT-LM/LLGuidance; завершенный вывод строго разбирается и проверяется, поэтому для всего значения JSON требуется достаточный `maxTokens`.
- `maxTokens` принимает целые числа от 1 до 2 147 483 647. Если его опустить, число выходных токенов определяется моделью или движком; защитный предел вывода провайдера 64 KiB сохраняется. `temperature` должен быть конечным и неотрицательным, `topK` - положительным целым, а `topP` - конечным числом от 0 до 1. Если все три параметра sampling опущены, сохраняются настройки модели или engine; при частичном переопределении пропуски заполняются базовыми значениями LiteRT-LM: `topK: 1`, `topP: 0.95`, `temperature: 1`.
- Поток использует конечные credits и ограниченные chunks, исключая неограниченный буфер и callbacks без обратного давления.
- Количество токенов usage берется непосредственно из счетчиков KV cache и decode объекта Conversation LiteRT-LM без оценки по числу символов. `durationMillis` измеряет только вызов генерации плагина и не включает обнаружение, привязку, перечисление моделей и диспетчеризацию хоста.
- Постоянный `ai.session` допускает один активный ход и сохраняет нативный Conversation после нормального завершения; после отмены, timeout, ошибки генерации или явного закрытия его нужно создать заново.
- Отмена, закрытие сеанса и timeout прекращают публикацию и завершают запрос одним конечным состоянием.
- В Настройки > Модели и сервисы откройте "Сведения о сервисе" и включите "Ввод изображений" в меню строки каждой модели из списка, которая принимает изображения. В существующих сервисах он по умолчанию отключен. Изображения отправляются только этому сервису. LiteRT и постоянный ai.session остаются текстовыми; снимки Agent требуют Android 11+, совместимых версий AutoJs6 и AI Agent, группы observe и включенного ввода изображений для точно выбранной модели.
- AiGoCode gpt-5.6-sol прошел реальные проверки с исходным изображением и изображением в результате инструмента на Provider 1.2.0 / build 218. Эти проверки с синтетическими изображениями не подтверждают поддержку других целей или выполнение полной визуальной задачи Agent.
- Ошибки онлайн-генерации передают только фиксированные категории `ONLINE_*` в необязательном поле `providerCode`. Неизвестные исключения не имеют категории; URL, учётные данные, ответы сервиса и исходный текст исключений исключены. Код ошибки и политика повторов не меняются.

### Необъявленные возможности

******

- Интерфейс плагина не объявляет вывод reasoning, поэтому скрипты не получают размышления (они показываются только в чате лаунчера). Локальные цели LiteRT-LM по-прежнему не объявляют tools.
- Разрешено до 16 раундов и 32 ожидающих вызовов. Результаты должны точно соответствовать ожидающему пакету; ограничения контекста/вывода, отмена и исходный срок сохраняются. Нативные инструменты не совмещаются с постоянными сессиями ai.session; начальная история не принимает роль tool.
- Загрузка файлов моделей с произвольных URL не поддерживается. Список моделей можно обновлять из публичного каталога проекта, но это не создает сервисы и не проверяет права доступа аккаунта. Чат launcher и AI Provider V2 показывают только импортированные локальные модели и явно настроенные онлайн-сервисы; локальные модели для загрузки ограничены закрепленными встроенными рекомендациями.
- Вывод NPU не объявлен: profile виден как `unavailable` с причиной `npu-runtime-not-packaged`. GPU объявляется только при загрузке `libOpenCL.so`, а расширение `.litertlm` по-прежнему не гарантирует инициализацию модели.

* `Функция` В чате теперь видно, как модель размышляет (Claude 5 и новее, Gemini 2.5 и новее, а также OpenAI-совместимые сервисы, которые возвращают размышления, например DeepSeek): пока ответ создается, размышления появляются в карточке над ним; когда ответ готов, карточка сворачивается в строку "Размышления: N с", нажатие раскрывает или сворачивает ее. Размышления сохраняются вместе с беседой, но не зачитываются вслух и не находятся поиском по сообщениям. Параметры "Показывать размышления во время ответа" и "Сворачивать размышления после ответа" по умолчанию включены, их можно выключить. Скрипты, вызывающие ИИ через плагин, размышления не получают
* `Исправление` Генерируемый ответ останавливался при повороте экрана, смене темной темы, языка или размера текста сообщений; теперь ответ продолжает генерироваться, а ответ, завершившийся, пока вы были вне чата, показывается полностью при возвращении
* `Исправление` После нажатия "Остановить" онлайн-запрос продолжал работать в фоне до конца ответа (и по-прежнему учитывался в расходе); теперь нажатие "Остановить" обрывает запрос в течение 1 секунды, так же как создание нового диалога, переключение диалога, смена модели и удаление сообщений
* `Исправление` Новые модели Claude отклоняли запросы профилей Anthropic, в которых задана температура, Top K или Top P; теперь профили Anthropic не отправляют эти три параметра, и страница настроек об этом сообщает
* `Исправление` После смены модели по умолчанию в профиле уже открытый новый разговор без сообщений продолжал использовать старую модель по умолчанию; теперь он переходит на новую модель по умолчанию (если в этом разговоре не выбрана вручную другая модель)
* `Исправление` При добавлении или изменении онлайн-профиля свайп вниз по форме легко закрывал ее, и все введенное терялось; теперь форма закрывается только кнопкой закрытия в правом верхнем углу, кнопкой "Отмена" или кнопкой "Назад", перед отменой несохраненных изменений спрашивает подтверждение и сохраняет введенное при повороте экрана
* `Исправление` Сбой автоматического обновления каталога онлайн-моделей после переноса документации Gemini и изменения формата ее таблиц

* `Функция` Приложения с независимой подписью запрашивают доступ к ИИ в плагине с привязкой к идентичности и установке; отзыв в настройках останавливает активные запросы

* `Исправление` Следующий запрос AI завершался ошибкой, если служба останавливалась до закрытия предыдущего сеанса
* `Исправление` Последовательные запросы AI отклонялись, пока отмененный сеанс модели еще закрывался
* `Исправление` Профили Anthropic всегда отправляли max_tokens=1024, даже когда максимум выходных токенов был не ограничен, поэтому ответы обрывались примерно на 1024 токенах без какого-либо уведомления (модели Claude, думающие по умолчанию, учитывают в нем и размышления); теперь по умолчанию запрашивается 16384 токена, а ответ, остановленный на лимите вывода, помечается под сообщением как "Достигнут лимит вывода" (также для OpenAI-совместимых профилей и Gemini)

* `Исправление` При сбое облачной генерации или проверки подключения показывалась только фиксированная категория сбоя, а настоящая причина (например, исчерпанный баланс аккаунта) оставалась неизвестной; теперь под сообщением о сбое выводятся HTTP-статус и пояснение самого провайдера (не более 300 символов, ключи маскируются)

### Сборка

******

```powershell
.\gradlew.bat :app:assembleDebug
```

Релизная сборка:

```powershell
.\gradlew.bat :app:assembleRelease
```

Параметры берутся из `version.properties`. Текущий минимальный SDK 24, целевой SDK 36, требуется JDK 21 или новее.

ABI протокола предоставляется локальными AAR репозитория в `libs`:

```text
common-plugin-api.aar
protocol-wire-api.aar
ai-common-api.aar
ai-provider-api.aar
```

Runtime использует LiteRT-LM 0.15.0 из Maven. Релиз сохраняет классы LiteRT-LM и создает два APK для ABI и один universal APK.

******

Исходный код проекта распространяется по MPL-2.0. LiteRT-LM и другие сторонние компоненты сохраняют свои лицензии.
