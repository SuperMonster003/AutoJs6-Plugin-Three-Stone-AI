# v1.7.0

###### 2026/11/12

* `修复` 长对话中较早的内容会被自动整理成摘要以节省上下文, 但部分在线服务和本地模型返回的摘要外面包着 Markdown 代码块标记或附带说明文字, 整理因此失败, 模型更容易忘记较早的对话内容; 现在会先去掉这些标记和说明再读取摘要
* `优化` 设置页重新整理: 首页只保留外观设置与 "会话", "模型与服务", "语音", "隐私与权限", "更新与关于" 5 个入口, 每项设置只出现在一处; "会话" 里的 "生成" 改名为 "输出长度与采样", 编辑时下滑或点到表单外不再会关闭表单, 有未保存的修改时会先询问; 版本历史移到 "更新与关于". 聊天页的菜单与侧边栏去掉了单独的 "模型" 入口, 统一从 "设置" 进入; 在 AutoJs6 里打开本插件的设置会直接进入 "模型与服务", 按返回键回到设置首页
* `优化` 原来的 "模型" 页与 "在线服务" 页合并为 "模型与服务" 页: 顶部是默认目标与 "允许移动网络和按流量计费网络", 下面分为 "在线服务" 与 "本地模型" 两段. 每个服务和本地模型都显示为同样的卡片, 用标签标出 "默认", "已就绪", "缺 API Key" 或 "不可用"; 设为默认, 测试, 重命名, 克隆, 清除 API Key, 删除等操作在卡片右侧的菜单里, 导入 / 导出服务, 刷新预置模型, 清理未引用文件等操作在段标题右侧的菜单里. 点按本地模型可以查看详情并复制模型 ID. 在线档案统一改称 "服务"
* `优化` 原来的 "默认在线目标" 与本地模型的 "选中" 合并为一个 "默认目标", 可以是任一在线模型或本地模型, 新会话与未指定模型的脚本都使用它, 升级后沿用原来的默认设置. 默认目标暂时不可用 (例如清除了 API Key) 时自动改用其他可用的模型, 恢复后改回; 默认目标所在的服务或模型被删除后, 也会自动改用其他可用的模型. 服务里的 "默认模型" 改名为 "首选模型"

# v1.6.0

###### 2026/11/12

* `新增` 在线档案可以设置默认推理强度 (低, 中, 高, 超高, 最高; 选 "默认" 时由模型自行决定), Anthropic 档案还可以默认使用快速模式 (回复更快, 但价格更高); 聊天时也可以只为当前会话调整, 调整随会话保存, 新会话从档案的默认值开始. 模型不支持所选档位时, 自动改用最接近的较低档位
* `新增` 切换模型改为从底部弹出的面板: 可以搜索, 按档案分组, 常用模型可以收藏并置顶, 每个模型标出是否支持图片输入, 推理与快速模式; 面板里可以直接调整当前会话的推理强度与快速模式, 底部的 "管理模型与服务" 直达模型设置. 聊天页顶部会显示当前会话的推理强度与快速模式
* `新增` 聊天时可以看到模型的思考过程 (支持 Claude 5 及更新的模型, Gemini 2.5 及更新的模型, 以及会返回思考内容的 OpenAI 兼容服务, 例如 DeepSeek): 回复生成时, 思考内容在回复上方的卡片里实时显示, 完成后折叠成 "思考了 N 秒", 点按可展开或收起. 思考内容随会话保存, 但不会被朗读, 搜索消息时也不会匹配. 设置中的 "生成中显示思考内容" 与 "结束后自动折叠" 默认开启, 可按需关闭. 脚本通过插件调用 AI 时不返回思考内容
* `修复` 旋转屏幕, 切换夜间模式, 更改语言或消息字体大小时, 正在生成的回复会被停止; 现在回复会继续生成, 离开聊天页期间生成完的回复, 回来时会完整显示
* `修复` 点 "停止" 后云端请求并没有立即断开, 而是在后台一直运行到回复生成完 (仍会计入用量); 现在点停止后 1 秒内断开请求, 新建会话, 切换会话, 切换模型和删除消息时也一样
* `修复` Anthropic 档案设置了温度, Top K 或 Top P 时, 较新的 Claude 模型会拒绝请求; 现在 Anthropic 档案不再发送这三项, 设置页也注明了这一点
* `修复` 在档案里修改默认模型后, 已经打开但还没发消息的新会话仍使用原来的默认模型; 现在会改用新的默认模型 (在该会话里手动选过其他模型的除外)
* `修复` 添加或编辑在线档案时, 在表单上往下滑很容易让表单收起, 已填写的内容随之丢失; 现在表单只能用右上角的关闭按钮, "取消" 或返回键关闭, 有未保存的内容时会先询问, 旋转屏幕后已填写的内容也会保留
* `修复` Gemini 官方文档迁移和表格格式变化导致在线模型目录自动更新失败的问题

# v1.5.0

###### 2026/11/04

* `新增` 独立签名应用可在插件中请求 AI 访问授权, 绑定应用身份与安装记录, 支持在设置中撤销授权并停止运行中的请求
* `新增` 生成回复期间保持屏幕常亮, 不再因屏幕超时而熄屏
* `修复` AI 服务在会话关闭完成前停止时, 后续请求因残留会话占用而失败的问题
* `修复` 取消后的连续 AI 请求因上一模型会话尚未释放而被拒绝的问题
* `修复` Anthropic 官方接口在 "最大输出 token" 设为不限制时固定按 1024 个 token 请求, 回复常在约 1024 个 token 处被截断且没有任何提示 (默认开启思考的 Claude 模型把思考也计入其中); 现在默认按 16384 个 token 请求, 回复因达到输出上限而中断时在消息下方标注 "已达输出上限", OpenAI 兼容接口与 Gemini 的同类情况也同样标注
* `修复` 连接测试只允许模型输出 8 个 token, 默认开启思考的 Claude 模型会把这点额度全部用于思考而返回不了文本, 导致配置正确的 Anthropic 资料被判为响应无效; 现在放宽到 1024 个 token
* `修复` 云端生成失败或连接测试失败时只显示固定的失败类别, 看不到具体原因 (例如账户余额不足); 现在会在失败信息下方附上 HTTP 状态码与提供方返回的说明 (最长 300 个字符, 密钥会被遮盖)

# v1.3.0

###### 2026/10/15

* `新增` 统一独立设置的平面分组, 行规格与居中圆角对话框. 语言, 夜间模式, 主题色与启动器图标均在确定后生效, 取消不改变已保存的设置. 主题色默认跟随 AutoJs6, 提供统一色板, HEX/RGB 输入与局部预览; 中性底色保持稳定, 控件遵循所选主题. 启动器默认自适应自动, 升级保留明确保存的选择.
* `修复` 经 OpenAI 兼容网关调用 Claude 或 Gemini 等模型时, 无参数工具的原生调用会以空字符串而非 "{}" 作为 arguments 流出, 会话把它判为无效响应并以 ONLINE_INVALID_RESPONSE 结束 (3-Stove Agent 在 AIGoCode 网关上的 Claude Code Ex 首个工具轮与 Gemini Ex 的一轮均因此失败); 现在空白 arguments 按空对象处理, 回放给模型的助手消息也使用规范化后的形式
* `修复` 原生工具续轮此前从首次请求的输出 token 上限中逐轮扣除已用输出, 长任务在约十轮后因上限耗尽而以 ONLINE_INVALID_RESPONSE 结束 (3-Stove Agent 的计算器用例在 Claude Code Ex 与 Gemini Ex 上均于第 9 到 14 次调用失败); 现在每个续轮都沿用完整的上限, 总量由调用方的任务预算约束, 与 2026-09-29 续轮超时重置的决定一致
* `修复` Gemini GenerateContent 协议把工具声明与 responseSchema 中的 JSON Schema 原样发送, 官方接口对 additionalProperties 等它不认识的关键字直接返回 HTTP 400 ("Unknown name additionalProperties"), 3-Stove Agent 的每个原生工具任务都在第一次调用时以 ONLINE_REQUEST_REJECTED 失败; 现在只保留 Gemini 支持的子集 (type, enum, properties, required, items, anyOf, minimum / maximum, minLength / maxLength, default 等), 调用方仍按完整 Schema 校验参数与回复
* `修复` 补齐模型采样和在线提供方设置的多语言翻译
* `修复` 阿拉伯语界面中, 3-Stone AI, 4-bit 与以数字开头的模型修订号不再被倒序或拆开显示 (例如 Stone AI-3, bit-4)
* `优化` 关于页面保留图标圆角描边容器, 透明内部透出与容器外侧一致的页面底色; 启动器图标选项从顶部展示并采用较小的说明文字.
* `优化` 启动器与插件中心图标按统一视觉尺寸标准调整, 插件中心采用透明背景和黑白或中性灰阶图案
* `优化` 插件中心图标采用统一工作台调整后的尺寸, 位置, 亮暗图稿与圆形底色, 保留可重建原稿和参数
* `优化` Android 系统应用信息图标与图标工作台共用图稿和亮暗底色, 保留插件中心透明图稿及现有启动器选项
